# 안산 빈집 안전 SOS: AI 분류 설계와 개발 계획

## 설계 원칙: 보는 건 AI, 판단은 규칙

이 시스템에서 AI는 **사진·영상·문서를 읽어 구조화된 사실로 바꾸는 일**과 **사람이 읽을 문장을 쓰는 일**만 한다. 점수 계산, 등급, 부서 배분, 경찰 전달 같은 **판단은 규칙**으로 한다.

이렇게 나누는 이유는 세 가지다.
- 심사위원이 "AI가 틀리면?"이라고 물을 때, 틀릴 수 있는 곳이 어디인지 정확히 말할 수 있다.
- 규칙은 시 담당자가 직접 고칠 수 있다. AI 모델을 다시 학습할 필요가 없다.
- 행정 결정(경찰 통보, 소유자 통지)을 AI가 단독으로 내리지 않는다.

## 1. 전체 흐름과 AI 위치

```
[공공데이터] ─▶ ① 지수 계산 ─▶ 격자 SOS 지도 (지자체)
                                   │ 이번 달 SOS 칸
                                   ▼
                          ② 점검 경로 생성 ─▶ 순찰대 폰
                                   │
            ┌──────────────────────┼──────────────────────┐
            ▼                      ▼                      ▼
   ③ 1분 사진 점검 [AI]    ④ 걷기 조도 점검 [AI]    ⑤ 주민 제보 [AI]
            └──────────────────────┼──────────────────────┘
                                   ▼
                       ⑥ 지수 갱신 (규칙 + 확률 갱신)
                                   ▼
                ⑦ 출력: 경찰 · 관제센터 · 시 [규칙 배분 + AI 문장]
```

| 단계 | AI가 하는 일 | 규칙이 하는 일 | 쓰는 기술 |
|---|---|---|---|
| ① 지수 계산 | (선택) 빈집 확률 모델, 유형 군집 | 지표 등급화, 두 축 점수, 네 칸 분류 | pandas, Jenks, scikit-learn |
| ② 경로 생성 | 지점별 "무엇을 볼지" 한 줄 | 시간 안에 점수 합이 최대인 경로 | OR-Tools |
| ③ 사진 점검 | 외관 체크리스트 판독, 얼굴·번호판 가림 | 체크 결과 → 관리 신호 점수 | 멀티모달 LLM, 얼굴·번호판 검출 |
| ④ 조도 점검 | 등 검출, 켜짐/꺼짐, 어두운 구간 | 구간 판정 기준, 지도 매칭 | 객체 검출, OpenCV |
| ⑤ 주민 제보 | 제보 유형 분류, 무관 사진 거르기, 가림 | 중복 묶기, 처리 상태 | 멀티모달 LLM |
| ⑥ 지수 갱신 | — | 관측값 반영, 빈집 확률 갱신 | 베이즈 갱신(단순 곱셈) |
| ⑦ 출력 | 대상별 설명문·리포트 작성 | 부서 배분, 경찰·관제 목록 선정 | LLM 문장 생성 |

## 2. ① 지수 계산

AI가 핵심이 아닌 단계다. 부산식 규칙 점수를 기준선으로 만들고, AI는 선택 사항으로 얹는다.

### 격자와 지표

- 안산 행정 경계 안에 **150m 격자**를 만든다(100~250m 중 데모 지도 가독성 기준) [추정].
- 각 건물(건축물대장)을 격자에 넣고, 격자별로 지표를 집계한다.

| 축 | 지표 | 계산 | 방향 |
|---|---|---|---|
| A 빈집 위험 | 노후 저층 비율 | 30년 이상 + 비아파트 + 4층 이하 건물 수 ÷ 전체 주거 건물 수 | 높을수록 위험 |
| | 평균 건축 연령 | 사용승인일 기준 | 높을수록 위험 |
| | 소형 필지 비율 | 대지면적 하위 30% 건물 비율(대지·건축면적을 하나로 합침) | 높을수록 위험 |
| | 공시지가 | 격자 평균 | **낮을수록** 위험 |
| | 고령화비율 | 행정동 값 배분 | 높을수록 위험 |
| | 인구 증감률 | 행정동 값 배분 | 감소할수록 위험 |
| | 정비 단계 | 이주 개시~철거 전 구역이면 최고점 | 해당 시 최고 |
| B 야간 치안 공백 | CCTV 거리 | 격자 중심에서 가장 가까운 방범 CCTV까지 m | 멀수록 위험 |
| | 보안등 밀도 | 격자 안 보안등 수 ÷ 도로 길이 | 낮을수록 위험 |
| | 꺼진 등·어두운 구간 | ④ 현장 관측값 | 많을수록 위험 |
| | 비상벨 | 격자 안 유무 | 없으면 위험 |
| | 무질서 신호 | 무단투기 CCTV, ③⑤ 투기 관측 | 많을수록 위험 |

### 점수 계산 (기준선)

1. 지표마다 Jenks로 1~5등급을 매긴다. 방향이 반대인 지표(공시지가 등)는 등급을 뒤집는다. 이 처리를 코드와 문서에 명시한다. 부산 보고서는 이 부분이 적혀 있지 않았다.
2. A축 점수 = A 지표 등급 평균, B축 점수 = B 지표 등급 평균.
3. 네 칸 분류: A ≥ 3.5 그리고 B ≥ 3.5 → **SOS**. 기준값은 화면에서 슬라이더로 조정할 수 있게 둔다.

### AI를 얹는 선택지 (해커톤에서 하나만)

| 선택지 | 하는 일 | 정답 데이터 | 데모 가치 |
|---|---|---|---|
| **유형 군집** | K-Means로 SOS 칸을 "정비 대기형", "구도심 다가구형" 같은 유형으로 묶음. 부산이 쓴 방법과 같음 | 필요 없음 | **추천.** 정답 없이 바로 가능 |
| 전이 학습 | 공주·양산 공개 빈집 데이터로 건물 단위 빈집 확률 모델을 학습해 안산 건물에 적용 | 타 지역 공개 데이터 | 중. 도시 성격 차이 설명 필요 |
| PU 학습 | 이주 완료 단지를 확실한 빈집으로 두고 학습 | 이주 완료 단지 | 정비 공가 전용으로만 |

### 설명 (왜 SOS인가)

기준선은 등급의 평균이라 **각 지표가 점수에 얼마나 기여했는지 바로 계산된다.** 복잡한 설명 기법이 필요 없다. 기여도 상위 3개를 LLM에 넘기면 대상별 문장을 쓴다.

> 예시 입력: `{격자: G-1423, A: 4.2, B: 4.0, 상위요인: [노후저층비율 5등급, CCTV거리 210m 5등급, 꺼진등 3개]}`
> 시 담당자용 출력: "노후 저층 주택 비율이 안산 상위 10%이고, 가장 가까운 방범 CCTV가 210m 떨어져 있습니다. 지난 점검에서 꺼진 등 3개가 확인됐습니다."

## 3. ② 점검 경로 생성

- **문제 형태:** 순찰대가 출발지에서 60분 안에 돌 수 있는 범위에서, 방문 지점들의 점수 합을 최대로 만드는 경로. 오리엔티어링 문제라고 부른다.
- **지점 후보:** 이번 달 SOS 칸 안에서 A축 기여가 큰 건물, B축 관측이 오래된 구간.
- **도구:** OR-Tools로 도보 거리 행렬(OSRM 또는 직선거리 × 1.3 근사)을 넣어 푼다. 지점 20개 이하라 몇 초면 끝난다.
- **AI 역할:** 지점마다 "이 지점에서 볼 것"을 한 줄로 만든다. 예: "개구부와 우편물 확인, 골목 끝 보안등 2개 점등 확인".

AI가 아니라 최적화다. 발표에서 이걸 AI라고 부르지 않는다.

## 4. ③ 1분 사진 점검 (핵심 AI 1)

### 흐름

```
촬영(2~3장) → 품질 검사 → 얼굴·번호판 가림 → 멀티모달 LLM 판독(JSON)
→ 규칙 점수 → 사람 확인(애매 항목만) → 저장
```

### 단계별 구현

**1) 품질 검사 (규칙, 폰에서)**
- 흐림: 라플라시안 분산이 기준 이하이면 "다시 찍기".
- 어두움: 평균 밝기가 기준 이하이면 "플래시 켜기".
- 위치: GPS 정확도가 30m보다 나쁘면 경고.

**2) 개인정보 가림 (AI, 서버에서 LLM 호출 전)**
- 얼굴: 공개 얼굴 검출 모델(예: MediaPipe, YuNet)로 찾아 블러.
- 번호판: 공개 번호판 검출 모델 또는 영역 검출 후 블러.
- 문패·주소 표지: 문자 검출(OCR 검출 단계만)로 글자 영역을 블러. 시간이 없으면 생략하고 "향후 과제"로 둔다.
- **원본은 저장하지 않는다.** 가린 사진만 저장하고 LLM에도 가린 사진만 보낸다.

**3) 판독 (멀티모달 LLM)**
- 입력: 가린 사진 2~3장, 체크리스트 지시문, 판단 예시 사진 3~4쌍(few-shot).
- 출력: 아래 JSON 스키마를 강제한다. 자유 문장은 받지 않는다.

```json
{
  "image_usable": true,
  "items": {
    "opening_state":   {"value": "closed|open|broken|boarded|unknown", "confidence": 0.0},
    "window_damage":   {"value": "none|partial|severe|unknown", "confidence": 0.0},
    "mail_accumulation":{"value": "none|some|heavy|unknown", "confidence": 0.0},
    "dumping":         {"value": "none|some|heavy|unknown", "confidence": 0.0},
    "overgrowth":      {"value": "none|some|heavy|unknown", "confidence": 0.0},
    "entry_traces":    {"value": "none|possible|clear|unknown", "confidence": 0.0},
    "structural_risk": {"value": "none|possible|clear|unknown", "confidence": 0.0},
    "nearby_lamp_visible": {"value": "yes|no|unknown", "confidence": 0.0}
  },
  "evidence": {"opening_state": "사진 2, 1층 현관문이 약 30cm 열려 있음"},
  "uncertain_reason": ""
}
```

- 지시문의 핵심 문장:
  - "보이지 않으면 반드시 unknown으로 답한다. 추측하지 않는다."
  - "사람이 사는지 비었는지는 판단하지 않는다. 보이는 상태만 답한다."
  - "evidence에는 어느 사진의 어느 부분인지 적는다."
- 모델은 속도와 비용을 고려해 중형 멀티모달 모델(예: claude-sonnet-5-5)을 쓰고, 대량 처리 시 소형 모델(예: claude-haiku-5-5)로 비교한다 [추정].

**4) 관리 신호 점수 (규칙)**

| 항목 | 값별 점수 |
|---|---|
| 개구부 | closed 0 / boarded 1 / broken 3 / open 4 |
| 창 파손 | none 0 / partial 2 / severe 3 |
| 우편물 적체 | none 0 / some 1 / heavy 3 |
| 투기물 | none 0 / some 1 / heavy 2 |
| 방치 식생 | none 0 / some 1 / heavy 2 |
| 출입 흔적 | none 0 / possible 2 / clear 4 |
| 구조 위험 | none 0 / possible 2 / clear 4 |

- confidence가 0.6 미만이거나 unknown인 항목은 점수에서 빼고 "사람 확인" 표시를 단다.
- 가중치의 근거: 필라델피아 실험에서 효과가 있었던 것은 **문·창 정비**였고 청소만은 효과가 없었다 [확인, South 2022]. 그래서 개구부와 출입 흔적에 높은 점수를 준다.

**5) 사람 확인 (애매 항목만)**
- 대원 폰에 "AI가 확신하지 못한 항목 2개"만 보여 주고 탭 한 번으로 고치게 한다.
- 고친 값은 그대로 **정답 데이터**로 쌓인다. 나중에 판독 정확도를 재고 예시 사진을 바꾸는 데 쓴다.

### 평가 방법 (해커톤 전에 반드시)

- 팀이 찍은 사진 100~200장을 팀원 2명이 따로 판정한다.
- **사람-사람 일치도**와 **AI-사람 일치도**를 항목별로 잰다(일치율과 코헨 카파).
- 발표에서 보여 줄 표: "개구부 판독 AI-사람 일치율 ○%, 사람끼리 ○%". AI가 사람끼리만큼 맞으면 충분하다는 논리다.

## 5. ④ 걷기 조도 점검 (핵심 AI 2)

### 핵심 아이디어: 낮에 등을 찾고, 밤에 켜졌는지 본다

꺼진 등은 밤 영상에서 "안 보이는 것"이라 밤 영상만으로는 찾기 어렵다. 그래서 **같은 경로를 낮과 밤에 한 번씩** 걷는다.

| 단계 | 낮 영상 | 밤 영상 |
|---|---|---|
| 찾는 것 | 가로등·보안등 **기둥과 등기구 위치** | 등이 **켜져 있는지**, 길이 **얼마나 밝은지** |
| 방법 | 프레임마다 등기구 검출 → GPS로 위치 추정 → 같은 등 묶기 | 낮에 찾은 등 위치 근처에 밝은 점이 있는지 확인 |
| 결과 | 등 목록(위치) | 등별 켜짐/꺼짐, 구간별 상대 밝기 |

보안등 공공데이터에 안산 위치가 있으면 낮 영상은 생략할 수 있다. 없을 때를 대비한 설계다.

### 구현

**1) 촬영 규칙 (밤)**
- 스마트폰 카메라를 **노출·ISO 고정**(수동 모드 또는 노출 잠금 앱). 자동 노출이면 어두운 곳을 밝게 만들어 비교가 깨진다.
- 가슴 높이, 정면, 걷는 속도 일정. GPS 기록 앱을 같이 켜서 시간-위치 로그를 남긴다.

**2) 프레임 추출과 위치 매칭**
- 초당 2프레임 추출. 각 프레임 시간에 GPS 로그를 보간해 위치를 붙인다.
- GPS 흔들림은 도로망(OpenStreetMap)에 붙이는 지도 매칭으로 줄인다. 시간이 없으면 이동 평균으로 대신한다.

**3) 등 검출**
- **낮:** 등기구 검출은 열린 어휘 검출 모델(예: "street lamp", "street light"로 검색하는 OWL-ViT, Grounding DINO 계열)로 시작한다. 학습 없이 바로 쓸 수 있다. 정확도가 부족하면 팀 사진 200장 정도에 라벨을 달아 소형 검출 모델(YOLO 계열)을 미세조정한다.
- **밤:** 프레임 위쪽 절반에서 밝기 상위 영역을 임계값으로 잡고 연결 영역을 찾는다(OpenCV). 크기·원형도로 차량 불빛, 간판을 걸러낸다. 간판은 색과 모양으로 거르되 완벽하지 않으니 "켜짐" 판정은 낮에 찾은 등 위치 근처의 밝은 점으로 한정한다.

**4) 꺼진 등 판정 (규칙)**
- 낮에 찾은 등 위치에서 15m 안을 지나는 밤 프레임들 중, 그 방향에 밝은 점이 한 번도 없으면 **"꺼짐 후보"**.
- 다음 점검에서도 꺼짐이면 **"꺼짐 확정"** → 도로조명팀 조치 목록으로.

**5) 어두운 구간 판정 (규칙)**
- 각 프레임 **아래쪽 절반(바닥)**의 평균 밝기를 구한다. 노출이 고정돼 있으니 같은 영상 안에서는 비교가 된다.
- 경로를 10m 단위로 나눠 밝기를 평균한다.
- 영상 전체 중앙값의 50% 미만이 30m 이상 이어지면 **"어두운 구간"**.
- 균일도는 구간 최솟값 ÷ 구간 평균으로 계산한다. 국내 연구에서 범죄 두려움을 가장 잘 설명한 것이 밝기의 고른 분포였다 [검색요약].

**6) 한계와 표기**
- 절대 조도(lux)가 아니다. **같은 영상 안의 상대 밝기**다. 화면에 "상대 밝기"라고 쓴다.
- 기기마다 결과가 다르다. 같은 폰, 같은 설정으로 찍은 영상끼리만 비교한다.
- 가로등 밀도가 높은 곳에 범죄가 많다는 국내 분석이 있다(역인과 가능) [확인, 염윤호 2019]. 그래서 **등의 개수는 점수에 쓰지 않고 꺼진 등과 균일도만** 쓴다.

## 6. ⑤ 주민 제보

| 단계 | 처리 | AI/규칙 |
|---|---|---|
| 촬영 | 사진 1장 + 위치(자동) + 한 줄 설명(선택) | — |
| 가림 | ③과 같은 얼굴·번호판 가림 | AI |
| 분류 | `방치빈집 / 꺼진등 / 투기 / 비상벨·안전시설 훼손 / 기타 / 무관` + 근거 한 줄 | 멀티모달 LLM |
| 거르기 | "무관"(셀카, 음식 등)과 사람 얼굴이 주인공인 사진은 자동 반려 | AI + 규칙 |
| 중복 묶기 | 같은 유형이 30m 안, 7일 안이면 한 건으로 합치고 "제보 수"를 올림 | 규칙 |
| 반영 | 해당 격자 B축 관측에 "주민 제보"로 추가. 순찰대 다음 경로에 확인 지점으로 넣음 | 규칙 |
| 회신 | 처리되면 제보자에게 "확인됨/조치됨" 알림 | 규칙 |

**주민 제보는 바로 점수를 올리지 않는다.** 순찰대가 확인한 뒤에 반영한다. 허위·악의 제보로 특정 집이 찍히는 것을 막기 위해서다.

## 7. ⑥ 지수 갱신

### 관측값 반영 (B축)

- 꺼진 등 확정, 어두운 구간, 투기 관측이 들어오면 해당 격자의 B 지표 등급을 다시 계산한다.
- 관측에는 날짜가 있다. **90일이 지나면 가중치를 절반으로** 줄여 오래된 관측이 계속 남지 않게 한다 [추정, 기준값은 조정 가능].

### 빈집 확률 갱신 (A축, 건물 단위)

단순한 베이즈 갱신으로 충분하다.

1. **사전 확률:** 지수 또는 전이 모델이 준 건물별 빈집 확률. 없으면 격자 A점수를 0~1로 바꾼 값.
2. **관측 반영:** 사진 점검의 신호별 "빈집일 때 나타날 가능성 ÷ 아닐 때 나타날 가능성"(우도비)을 곱한다.
   - 예: 우편물 heavy는 우도비 4, 개구부 open은 3, 모두 none이면 0.5 [추정, 초기값].
3. **사후 확률이 0.7 이상**이면 "빈집 의심"으로 시에 넘긴다. 시가 확인하면 정답 데이터가 된다.
4. 정답이 쌓이면 우도비를 실제 값으로 다시 계산한다. 이게 "순찰이 쌓일수록 똑똑해진다"의 실체다.

## 8. ⑦ 출력: 누가 무엇을 받나

배분은 규칙, 문장은 AI다.

| 받는 곳 | 선정 규칙 | AI가 쓰는 것 |
|---|---|---|
| **도로조명팀** | 꺼짐 확정 등, 어두운 구간 | 위치 목록과 현장 사진 요약 |
| **건축과·빈집 담당** | 개구부 open/broken, 구조 위험, 빈집 의심 | 소유자 통지문 초안, 조치 권고 |
| **청소 부서** | 투기 heavy | 수거 요청 문장 |
| **지구대·파출소(경찰)** | SOS 칸 안 + 출입 흔적 clear 또는 개구부 open인 건물 → "범죄 취약 빈집 목록" | 지구대별 순찰 포인트 요약 |
| **관제센터** | SOS 칸 중심 반경 200m 안 방범 CCTV → 야간 시간대 중점 관제 목록 | 카메라별 "왜 지금 봐야 하나" 한 줄 |
| **시(정책)** | SOS 칸이 3개 이상 붙어 있는 덩어리 → 빈집 밀집구역 후보 | 구역별 근거 리포트(지표, 관측, 사진, 근거 조례) |

- 경찰과 관제센터에 넘기는 목록에는 **건물 주소 대신 격자·건물 ID**를 쓰고, 상세는 권한 있는 담당자만 연다.
- LLM이 쓴 문장에는 "AI 작성, 담당자 확인 필요" 표시를 붙인다.

## 9. 시스템 구성

```
[순찰대·주민 폰]  모바일 웹(PWA): 카메라, GPS, 경로 지도, 체크 확인
        │ 업로드
        ▼
[백엔드 API]  FastAPI
   ├─ 사진 처리: 품질검사 → 가림 → LLM 판독 → 규칙 점수
   ├─ 영상 작업 큐: 프레임 추출 → 등 검출 → 구간 판정 (비동기)
   ├─ 지수 엔진: 격자 집계, 등급화, 네 칸 분류, 확률 갱신
   ├─ 경로 엔진: OR-Tools
   └─ 출력 엔진: 규칙 배분 + LLM 문장
        │
        ▼
[DB]  SQLite + GeoJSON (해커톤) / PostGIS (실서비스)
        │
        ▼
[지자체 대시보드]  React + Leaflet 또는 deck.gl
```

## 11. 무엇이 틀릴 수 있고 어떻게 막나

| 위험 | 막는 방법 |
|---|---|
| LLM이 보이지 않는 것을 지어냄 | unknown 강제, evidence 필수, confidence 낮으면 사람 확인 |
| 사람이 사는 집을 빈집으로 찍음 | AI는 상태만 판독. 빈집 판정은 시가. 주민 제보는 순찰대 확인 후 반영 |
| 사진 속 개인정보 | LLM 호출 전 가림, 원본 미저장 |
| 차량 불빛·간판을 등으로 착각 | 켜짐 판정은 낮에 찾은 등 위치 근처로 한정 |
| 노출 차이로 밝기 비교가 깨짐 | 노출·ISO 고정, 같은 기기끼리만 비교, "상대 밝기" 표기 |
| 등 개수와 범죄의 역인과 | 등 개수는 점수에서 제외, 꺼진 등·균일도만 사용 |
| 시연 중 네트워크·API 실패 | 응답 캐시, 녹화 백업, 오프라인 모드 |
| 비용 | 사진 1건당 LLM 1회 호출. 대량이면 소형 모델로 1차 판독 후 애매한 것만 중형 모델 |

## 12. 발표에서 AI를 설명하는 한 문단

> AI는 두 가지를 합니다. 순찰대원이 찍은 사진과 영상을 읽어 "문이 열려 있다", "이 등이 꺼져 있다" 같은 사실로 바꾸고, 그 결과를 시 담당자와 경찰이 읽을 문장으로 씁니다. 점수와 판단은 시가 고칠 수 있는 규칙으로 합니다. 그래서 AI가 틀릴 수 있는 곳이 어디인지 정확히 보여 드릴 수 있고, 사람 판정과의 일치율도 공개합니다. 순찰이 쌓일수록 사람이 고친 값이 정답 데이터가 되어 판독과 지수가 함께 나아집니다.
