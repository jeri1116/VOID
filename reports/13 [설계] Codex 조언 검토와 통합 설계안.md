# Codex 조언 검토와 통합 설계안

## 한 줄 결론

Codex 조언은 **서비스 운영 설계로는 대부분 맞다.** 특히 색의 의미, 회색(미점검), 안전신문고 대응, 장소 단위 관리는 그대로 받아야 한다. 다만 그대로 따르면 **치안이 흐려지고, AI 역할이 거의 사라지고, 확인되지 않은 사실 몇 개가 섞인다.** 이 세 가지만 보완하면 된다.

> 표기: **[확인]** 원문 열람, **[검색요약]** 검색 요약에서만 확인, **[미확인]** 근거 못 찾음, **[추정]** 해석. 기준일 2026-11-07.

## 1. 그대로 받을 것

| Codex 조언 | 왜 맞나 | 우리 설계에 반영 |
|---|---|---|
| **색은 "범죄 위험"이 아니라 "점검·조치 우선순위"** | 확정되지 않은 빈집을 "범죄 위험"으로 칠하면 근거도 없고 소유자·동네 낙인이 생긴다 | 빨강 = 긴급 점검·조치, 주황 = 일반 점검·관리, 초록 = 최근 점검상 특이사항 없음 |
| **회색 = 미점검·정보 부족** | 제보가 없다고 초록으로 칠하면 "안전한 곳"과 "아무도 안 가 본 곳"이 섞인다 | 회색 추가. **회색이면서 SOS 지수가 높은 곳 = "가 봐야 할 곳"**으로 지수를 살린다 |
| **초록에 마지막 점검일 표시** | 초록은 "영원히 안전"이 아니다 | 점검 후 시간이 지나면 색이 흐려지고 90일이면 회색으로 돌아간다 [추정, 기준값 조정 가능] |
| **제보만으로 위험을 확정하지 않는다** | 허위·악의 제보 방지 | 확인 전 = 점선 테두리 "점검 요청", 순찰 확인 후 = 실선 "조치 필요" |
| **긴급 상황은 플랫폼이 아니라 119·112** | 화재·붕괴·진행 중 범죄를 대기열에 넣으면 안 된다 | 제보 첫 화면에 "지금 불·연기·위험한 사람이 있나요? → 119 / 112" 버튼 |
| **순찰대는 외관 확인과 기록만** | 사유지 진입·임의 수리는 권한 밖 | 순찰대 = 확인·기록, 조치 = 시·소유자·업체 |
| **핵심 문제는 "우선순위"와 "현장 정보의 시차"** | 우리 설계(SOS 지수 = 우선순위, 순찰 루프 = 시차 해소)와 정확히 맞다 | 문제 정의 문장에 반영 |
| **지수 계산을 주인공으로 삼지 말 것** | "보는 건 AI, 판단은 규칙" 원칙과 같다 | 지수는 회색 구역의 사전 정보로만 쓴다 |
| **차별점은 개별 민원이 아니라 장소 단위 반복 관리** | 안전신문고와 겹치지 않는 가장 확실한 지점 | **이걸 AI 기능으로 만든다** (3절) |

## 2. 보완할 것 세 가지

### ① 치안이 흐려진다

Codex는 목적을 "범죄예방·화재예방·시설안전·생활환경 개선을 포함한 종합적인 안전관리"로 넓혔다. 이러면 세 가지 문제가 생긴다.

- 해커톤 분야가 치안인데 **시설 관리 앱**으로 보인다.
- **안전신문고가 바로 그 "종합 생활안전 신고"다.** 범위를 넓힐수록 더 겹친다.
- 팀의 목표는 "치안을 더 좋게 하는 서비스"다.

**보완:** 화재·노후 제보는 받되, **우선순위의 첫 번째 축은 치안**으로 둔다.

| 제보 카테고리 | 성격 | 우선순위 가중 |
|---|---|---|
| 출입·침입 흔적 (문·창 열림, 사람 드나든 흔적) | **치안 핵심** | 가장 높음 |
| 조명·감시 공백 (꺼진 등, 어두운 골목) | **치안 핵심** | 높음 |
| 화재 위험 (인화성 폐기물, 전선 노출) | 안전 (방화와도 연결) | 중간 |
| 시설 파손·붕괴 징후 | 안전 | 중간 (붕괴 위험은 119로) |
| 투기·방치 | 생활환경 | 낮음 (청소만은 범죄 효과 없음 [확인, South 2022]) |

카테고리 체계는 지자체 빈집 안전조치 명령의 실제 항목과도 맞춘다. 동작구 공고에는 손상부 안전조치, 화재위험 안전조치, 오·폐기물 처리, 미관상 저해사항 조치가 대상으로 나온다 [검색요약]. 우리 카테고리는 여기에 치안 항목 두 개(출입 흔적, 조명 공백)를 앞에 붙인 구조다.

**발표 문장:** "치안 공백을 중심으로 보고, 같은 현장 점검에서 화재·붕괴 위험도 함께 잡습니다."

### ② AI 역할이 거의 없다

AI 해커톤인데 Codex 조언에는 AI가 사실상 빠져 있다. Codex가 "사진 분류 + 색칠은 차별점으로 부족하다"고 한 것은 맞다. 그래서 AI를 **Codex가 찾은 진짜 차별점(장소 단위 관리)을 가능하게 하는 곳**에 둔다. 3절에 정리했다.

### ③ 근거가 빠졌다

Codex는 "빈집이 증가한다고 반드시 범죄가 증가하는 것은 아니다"라고만 하고 근거를 들지 않았다. 맞는 말이지만, 우리에게는 이미 근거가 있다.
- 빈집 문·창 정비 시 주변 총기폭행 대조군 대비 −13% (South 2022 무작위 실험) [확인]
- 국내 빈집 밀도와 절도 정(+) (염윤호 2019) [확인]
- 정부 종합계획 "빈집 밀집 구역이 범죄·안전 등에 취약" [확인]

Codex의 "관리체계" 프레임은 **무엇을 만드나**에 대한 답이고, 우리의 논리 깔때기는 **왜 그게 치안에 중요한가**에 대한 답이다. 둘을 합친다.

## 3. AI가 들어가는 다섯 자리

| # | AI가 하는 일 | 왜 AI여야 하나 | 기술 |
|---|---|---|---|
| ① | **제보를 장소 사건 파일에 연결:** 새 제보의 위치·사진·글을 보고 "이미 있는 어느 건물 파일과 같은 곳인지" 판단해 묶는다 | GPS는 10~30m씩 틀리고, 글은 "편의점 뒤 빈집"처럼 쓴다. 규칙만으로는 같은 곳인지 못 가린다. **이게 안전신문고와의 차이를 만드는 기능이다** | 위치 후보 + 사진 유사도 + 글 속 장소 표현을 LLM이 비교 |
| ② | **제보 구조화와 긴급도 1차 분류:** 글과 사진에서 위험요소를 뽑고, "연기", "불", "사람이 갇혔다" 같은 긴급 신호면 즉시 119·112 안내 | 시민은 카테고리를 틀리게 고르거나 하나만 고른다 | 멀티모달 LLM, 정해진 JSON 출력 |
| ③ | **순찰대 사진 판독:** 외관 체크리스트 자동 채움 (기존 설계) | 자원봉사자 입력 부담 제거 | 멀티모달 LLM |
| ④ | **조치 전후 비교:** 같은 장소의 이전 사진과 조치 후 사진을 비교해 "문 폐쇄됨", "폐기물 제거됨"을 판정 | Codex가 말한 "사후관리의 연속성"을 사람이 일일이 대조하지 않게 한다 | 두 사진을 함께 넣고 항목별 변화 판정 |
| ⑤ | **사건 파일 요약과 부서 전달문:** 한 장소에 쌓인 제보·점검 이력을 한 문단으로 요약하고, 담당 부서별 요청문을 쓴다 | 담당자가 이력 10건을 다 읽지 않아도 된다 | LLM 문장 생성 |

우선순위 점수와 색 결정은 **규칙**이다. AI가 색을 정하지 않는다.

## 4. 통합 설계

### 장소 하나의 상태 흐름

```
[회색] 미점검
   │ 시민 제보 접수 (AI ①② : 장소 연결, 구조화)
   ▼
[주황/빨강, 점선] 점검 요청 ── 긴급 신호면 즉시 119·112 안내
   │ 순찰대 현장 확인 (AI ③ : 사진 판독)
   ├─▶ [초록] 특이사항 없음 (마지막 점검일 표시)
   ▼
[주황/빨강, 실선] 조치 필요 ── 부서 전달 (AI ⑤)
   │ 담당 부서·소유자 조치
   ▼
[초록] 조치 완료 ── 재점검에서 전후 비교 (AI ④)
   │ 시간 경과
   ▼
[흐려짐 → 회색] 90일 지나면 다시 점검 대상
```

### 우선순위 점수 (규칙)

| 요소 | 내용 | 비고 |
|---|---|---|
| 확인된 위험 심각도 | 출입 가능 + 인화성 폐기물 같은 조합이면 최고 | 순찰 확인 후에만 반영 |
| 치안 맥락 | 야간 감시 공백(CCTV 거리, 꺼진 등) | SOS 지수 B축 |
| 제보 반복 | 같은 장소 서로 다른 제보자 수 | 한 사람의 반복 제보는 1로 |
| 정보 신선도 | 마지막 점검 후 지난 일수 | 오래될수록 올라감 |
| 사전 위험 | 회색 구역에서 SOS 지수 A축(빈집 발생 위험) | **지수가 살아남는 자리** |
| 민감 장소 근접 | 학교·통학로·어린이공원 근처 | 아동 대상 범죄 예방 맥락. 가중치는 시와 협의 [추정] |

### 화면 세 개

| 화면 | 쓰는 사람 | 핵심 기능 |
|---|---|---|
| **시민 제보** | 주민 | ① 119·112 긴급 버튼 → ② 지도에서 위치 핀 → ③ 카테고리(AI가 제안) → ④ 제목·간단한 글 → ⑤ 사진(선택, 얼굴·번호판 자동 가림) → ⑥ 처리 상태 알림 |
| **순찰대 점검** | 자율방범대·반려견 순찰대 | 우선순위 높은 순 경로 → 지점 도착 → 사진(AI 판독) → 판정 3택(조치 필요 / 관찰 / 이상 없음) → 조치된 곳은 전후 사진 |
| **지자체 관리** | 시 담당자 | 장소 단위 사건 파일 목록, 색 지도, 부서 배분, 조치 상태 입력, 성과 지표 |

### 성과 지표 (Codex의 "지도가 의사결정을 어떻게 바꾸나"에 대한 답)

| 지표 | 의미 |
|---|---|
| 미점검(회색) 비율 | 아무도 안 가 본 곳이 줄었나 |
| 제보 → 현장 확인까지 걸린 일수 | 시차가 줄었나 |
| 확인 → 조치 완료까지 걸린 일수 | 실제 개선으로 이어졌나 |
| 재발률 | 조치 후 90일 안에 같은 위험이 다시 생겼나 |
| (장기) SOS 칸의 112 신고·체감 안전 | 치안이 나아졌나. 비교 설계로 |

## 5. Codex 조언 중 확인되지 않은 사실

슬라이드에 쓰기 전에 원문으로 확인해야 한다.

| Codex 주장 | 확인 결과 |
|---|---|
| "주민과 경찰도 학교 주변 공·폐가 등에서 발생할 수 있는 안전문제를 지속적으로 제기해 왔다" | **[미확인]** 학교 주변 합동점검(교통·식품·유해환경 등)과 하교 시간 합동순찰은 확인되지만, 공·폐가를 대상으로 한 점검은 찾지 못했다 |
| "안산시 공·폐가 환경개선사업" | **[미확인]** 안산시 학교시설 환경개선, 학교 주변 불법광고물 정비는 있지만 공·폐가 환경개선사업은 찾지 못했다 |
| "정부의 빈집 등급 산정에 주변 안전·통행·위생·경관 영향을 고려하도록 규정" | **[미확인]** 등급이 1~3단계이고 실태조사 세부 지침이 있다는 것만 확인. 시행규칙 별표를 직접 봐야 한다 |
| "안전신문고는 위험시설·화재 위험·쓰레기를 사진과 함께 신고하고 처리결과 확인" | 안전신문고의 일반 기능으로는 맞다. **빈집 전용 신고 유형이 있는지는 [미확인]** |
| "법령상 빈집 신고 후 현장조사와 안전조치 절차" | 안전조치 명령·이행강제금 절차는 있다 [검색요약]. 주민 "빈집 신고" 절차는 [미확인] |
| 가상 사례 "사이동" | 실제 행정동 이름이다. 가상 사례라도 실제 동 이름은 오해를 부른다. **"가상 A동"으로 바꾼다** |

## 6. "안전신문고가 있는데 왜?"에 대한 답

> 안전신문고는 위험 하나를 신고하면 처리하고 끝나는 민원 창구입니다. 같은 빈집에 대해 쓰레기, 문 파손, 꺼진 등이 세 번 따로 신고되면 세 건의 민원이 됩니다. 저희는 이걸 **한 장소의 사건 파일 하나**로 묶고, 순찰대가 확인하고, 조치 뒤에도 다시 확인합니다. 그리고 아무도 신고하지 않은 곳(회색) 중 위험해 보이는 곳을 먼저 찾아갑니다. 신고를 받는 서비스가 아니라, **신고가 오지 않는 곳까지 관리하는 서비스**입니다.

나중에 시가 도입하면 안전신문고의 빈집 관련 신고를 이 시스템의 입력으로 받을 수 있다고 덧붙인다. 경쟁이 아니라 연결이다.

## 7. 최종 문제 정의 (치안 중심으로 다듬음)

> **안산의 빈집 주변에서 생기는 야간 안전 공백을, 누가 언제 확인하고 고치는가?**
>
> 안산은 범죄 분야 지역안전지수 5년 연속 5등급이다. 노후계획도시 정비와 빈집 증가로 아무도 지켜보지 않는 장소가 늘고 있고, 시도 빈집이 범죄와 화재의 원인이 된다고 밝혔다. 그러나 빈집 실태조사는 몇 년에 한 번이고, 시민 신고는 건별로 처리되고 끝나며, 순찰대는 어디를 먼저 봐야 할지 알려 주는 도구가 없다.
>
> 이 서비스는 시민 제보와 빈집 정보를 장소 단위로 묶어 **점검·조치 우선순위**를 지도에 보여 주고, 순찰대가 확인한 결과와 시의 조치를 계속 반영한다. 목표는 문이 열린 빈집과 꺼진 등 같은 **치안 공백을 더 빨리 찾아 실제로 고치는 것**이고, 같은 점검에서 화재·붕괴 위험도 함께 잡는다.

## 8. 해커톤 전에 검증할 것 (Codex 제안 + 보완)

Codex 말대로, 문제가 안산에 실제로 있는지 확인해야 한다. 가장 빠른 방법은 **사람 두 명 인터뷰**다.

| 누구 | 물어볼 것 | 이 답이 확인해 주는 것 |
|---|---|---|
| **자율방범대 지대장 1명** | 순찰 경로는 어떻게 정하나? 빈집을 따로 보나? 본 걸 어디에 기록·보고하나? 꺼진 등을 보면 어떻게 하나? | "순찰대에 우선순위 도구가 없다"는 주장 |
| **안산시 빈집 또는 건축 담당자 1명** | 빈집 정보는 얼마나 자주 갱신되나? 주민 신고·안전신문고 빈집 신고는 어떻게 들어오나? 순찰 결과를 받는 경로가 있나? 매달 4일 안전점검은 어떻게 하나? | "정보가 흩어져 있고 시차가 있다"는 주장 |

인터뷰 결과 이미 잘 연결돼 있다면, 그것도 발표에서 솔직히 말하고 차별점을 "신고 안 오는 회색 구역 관리"로 좁힌다.

그 밖에 확인할 것:
- [ ] 안전신문고에 빈집·방치 건축물 신고 유형이 따로 있는지
- [ ] 소규모주택정비법 시행규칙의 빈집 등급 기준 별표
- [ ] 학교 주변 공·폐가 점검 제도가 실제로 있는지 (경찰청·교육부 보도자료)
