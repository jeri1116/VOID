## 1. 순찰대는 누구인가

| 후보 | 규모·근거 | 장점 | 단점 |
|---|---|---|---|
| 자율방범대 | 약 1,400명(2023) [검색요약], 지원 조례 있음 [확인] | 이미 조직·지대 체계가 있음, 순찰이 본업 | 기존 순찰 경로·시간이 정해져 있어 빈집 점검이 "추가 업무"가 됨 |
| 반려견 순찰대 | 지원 조례 2026-04-29 [확인] | 산책하며 자연스럽게 골목을 다님, 동네 주민 | 신설이라 규모·운영 미확인, 점검 의무를 주기 어려움 |
| 로보캅순찰대 | 약 420명 [검색요약], 2008년 시 조례 기반 | 시가 직접 운영하는 조직 | 활동 내용과 빈집 연계 가능성 미확인 |
| 동 살핌이(신규) | 종로구 방식: 동주민센터 추천 주민 | 자기 동을 가장 잘 앎, 동주민센터가 신뢰 창구 | 안산에 없는 제도. 새로 만들어야 함 |
| 시 점검반(공무원) | 계획상 점검 주체는 시 담당부서 | 판정·조치 권한이 있음 | 인력이 적음. 이게 문제의 출발점 |

**고려할 점:** 자원봉사 조직은 명부와 실제 활동 인원 차이가 크다. 안산 자율방재단은 명부 447명 중 실제 활동이 약 100명이라는 시의회 답변이 있었다 [확인]. 한 조직에만 기대면 위험하다.

**선택지:**
- A. 자율방범대 중심 (기존 조직 활용, 빠름)
- B. 동 살핌이 신설 중심 (종로 방식, 동네 밀착)
- C. 섞기: 자율방범대는 "지정 점검", 반려견 순찰대·주민은 "지나가다 발견"

## 2. 순찰대가 할 수 있는 일과 없는 일

| 할 수 있음 | 고민 필요 | 할 수 없음 |
|---|---|---|
| 공공도로에서 외관 관찰 | 이웃 주민에게 "이 집 비었나요?" 묻기 (현장조사의 '면담'과 겹침) | 사유지·건물 진입 |
| 외관 사진 촬영 | 전단·우편물 등 경미한 정리 | 문 열기, 잠금 확인을 위해 만지기 |
| 체크리스트 작성, 메모 | 경고판·출입금지선 부착 (계획상 시의 안전조치 항목) | 수리·봉쇄 |
| 긴급 시 119·112 신고 | 소유자·관리인과 대화 | 빈집 판정 |
| 꺼진 보안등·투기 등 시설 문제 신고 | | 소유자 정보 열람 |

**고려할 점:**
- 법상 현장조사(관찰·면담)는 시의 업무다. 순찰대가 하는 일은 **"조사"가 아니라 "관찰 기록"**으로 부르는 게 안전하다 [추정].
- "고민 필요" 칸은 시와 협의해 정할 부분이다. 해커톤에서는 "할 수 있음"만 시연하는 게 무난하다.

## 3. 점검이 시작되는 세 가지 경로

| 경로 | 시작 | 예시 | 고려할 점 |
|---|---|---|---|
| ① 지정 점검 | 시가 기한이 된 빈집을 배정 | 상시관리 빈집 6개월 점검 | 계획의 정기 점검을 그대로 실행. 배정 방식이 핵심 |
| ② 확인 요청 | 시민 제보가 들어옴 | "문이 열려 있어요" 제보 확인 | 빠르게 확인할수록 신뢰가 쌓임. 응답 기한을 둘지 |
| ③ 발견 | 순찰 중 우연히 봄 | 등록 안 된 집에 우편물이 잔뜩 쌓임 | 회색 구역 발굴. 등록 빈집이 아니어도 기록 가능하게 할지 |

## 4. 점검 한 번의 흐름 (초안)

```
배정 확인 → 이동 → 도착 확인(GPS) → 외관 관찰·촬영
→ AI가 체크리스트 작성 → 대원이 애매한 항목만 수정
→ 판정 선택 → 메모(선택) → 제출
   └ 긴급이면 이 흐름을 멈추고 119·112
```

**판정 선택지를 몇 개로 할지:**

| 안 | 선택지 | 장점 | 단점 |
|---|---|---|---|
| 3택 | 조치 필요 / 관찰 필요 / 이상 없음 | 단순, 빠름 | "못 봤음"을 표현할 수 없음 |
| 4택 | 위 3개 + **확인 불가**(가려져 안 보임, 접근 불가) | 데이터가 정직해짐 | 확인 불가가 많으면 쓸모없는 점검이 늘어남 |
| 5택 | 4택 + **빈집 아닌 것 같음**(사람이 사는 흔적) | 판정 오류(9호 거주확인 같은)를 현장에서 먼저 잡음 | 순찰대가 판정하는 것처럼 보일 수 있음 |

**고려할 점:** 한 번에 1~2분 안에 끝나야 지속된다. 항목이 늘수록 입력이 늘어난다.

## 5. 피드백은 어디로 흐르나

피드백은 한 방향이 아니라 **네 방향**이다.

| 방향 | 내용 | 왜 필요한가 |
|---|---|---|
| 순찰대 → 시 | 점검 결과(사진, 체크, 판정) | 계획의 "사진·일지 DB 축적"을 대신함 |
| 시 → 순찰대 | "당신이 본 집, 문 폐쇄 완료" 같은 처리 결과 | **자원봉사 지속의 핵심.** 본 게 반영돼야 다시 한다 |
| 시 → 시민 | 제보 처리 상태 | 안전신문고와 같은 기본 기능 |
| 순찰대 → AI | 대원이 고친 항목 | AI 판독 정확도 개선, 나중엔 예측 모델 정답 데이터 |

## 6. 순찰대 결과가 지도에 언제 반영되나 (중요한 결정)

| 안 | 방식 | 장점 | 단점 |
|---|---|---|---|
| A. 바로 반영 | 제출하면 즉시 지도 색이 바뀜 | 빠름, 순찰대가 결과를 바로 봄 | 잘못된 점검이 그대로 퍼짐 |
| B. 시 확인 후 반영 | 시 담당자가 검토하고 승인하면 반영 | 정확함, 행정 책임이 분명 | 담당자 업무가 늘고 느려짐. 담당자가 적은 게 원래 문제 |
| C. 섞기 | "이상 없음·관찰"은 바로 반영, "조치 필요"는 시 확인 후 빨강 확정. 확인 전에는 점선 표시 | 속도와 정확성 균형 | 상태가 많아져 화면이 복잡해짐 |

**고려할 점:** 담당자 승인을 필수로 하면 "인력 부족" 문제를 다시 만든다. 반대로 승인을 아예 없애면 행정이 결과를 믿지 않는다.

## 7. 조치 후 개선은 누가 확인하나

```
시: 조치 요청 → 담당 부서·소유자 조치 → "조치 완료" 입력
→ 순찰대: 재방문 확인 → 전후 사진 비교(AI) → 초록 전환
```

**선택지:**
- 조치 부서가 완료를 입력하면 바로 초록 vs **순찰대 재확인 후 초록**
- 재확인 기한을 둘지(예: 완료 입력 후 30일 안)
- 소유자가 스스로 고친 경우(계획의 "자율정비 우선")는 어떻게 들어오게 할지

**고려할 점:** 계획은 안전조치 완료 빈집도 순찰 대상으로 두고, 6개월~1년마다 다시 보라고 했다 [확인]. "한 번 고치면 끝"이 아니라 **다시 열리거나 다시 쌓이는지**를 보는 게 핵심이다.

## 8. 배정과 빈도

**규모 감:** 상시관리 123호 + 안전조치 21호 = 144호를 연 1~2회 → **연 144~288회** 점검 [추정 계산]. 다세대는 같은 건물에 여러 호가 있어 실제 방문지는 이보다 적다.

| 배정 방식 | 내용 | 장점 | 단점 |
|---|---|---|---|
| 동별 고정 담당 | 동마다 담당 대원 지정 | 책임이 분명, 동네를 앎 | 담당자가 빠지면 공백 |
| 우선순위 큐에서 선택 | 대원이 목록에서 골라 감 | 자율적, 부담 조절 | 인기 없는 곳이 남음 |
| **기존 순찰 경로에 끼워 넣기** | 원래 다니던 경로 근처 빈집만 자동 추가 | 추가 부담 최소 | 경로에서 먼 빈집은 안 다룸 |

## 9. 계속 하게 만드는 장치

- **처리 결과 알림:** "점검한 빈집 3곳 중 2곳 조치 완료"
- **봉사시간 인정:** 자원봉사 실적 연계 가능성 [추정, 시와 확인 필요]
- **활동 기록:** 대원·지대별 점검 이력. 자율방범대 지원 근거 자료로도 쓰임
- **주의:** 순위 경쟁을 붙이면 대충 찍은 점검이 늘 수 있다

## 10. 품질과 안전

**점검 품질**
- 도착 위치(GPS)와 촬영 시각을 자동 기록해 실제 방문 여부 확인
- 사진 없이는 제출 불가
- 같은 빈집을 다른 대원이 본 결과가 크게 다르면 표시
- AI 판독과 대원 판정이 크게 다르면 표시

**대원 안전**
- 건물 진입 금지
- 2인 1조 권장
- 안에 사람이 있는 것 같거나 위협을 느끼면 접근하지 않고 112
- 붕괴 징후가 있으면 가까이 가지 않고 119

## 12. 확인하면 좋은 것 (인터뷰)

- **자율방범대 지대장:** 지금 순찰 경로와 빈도, 순찰 기록 방식, 빈집을 따로 보는지, 스마트폰 앱을 쓸 수 있는 대원 비율
