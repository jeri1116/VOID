# 빈집 상시관리 솔루션 계획 (방향 확인용)

> 근거: `reports/24 [근거] 상시관리 솔루션 근거 정리.md`
> 이 문서는 22번(MVP 초안)을 대체하는 **새 방향 초안**이다. 숫자는 모두 초기값이다.

---

## 1. 한 줄

**안산시 빈집정비계획이 정한 "144호 정기 점검"을 실제로 돌리는 도구.** 이번 달 어디부터 갈지 정하고, 사진 한 장으로 점검 일지를 남기고, 상태가 나빠지면 조치로 넘긴다.

- **누가 쓰나:** 시 빈집 담당자(2027년 특별법의 전담조직), 시민(제보)
- **나중에 붙일 것:** 경찰·소방·동 행정복지센터 협업 순찰
- **하지 않는 것:** 빈집 판정(시가 함), 거래·활용(다른 팀 영역)

## 2. 공람안 조항 → 기능 (적합성의 핵심)

기능마다 근거가 되는 안산시 계획서 문장이 있다. "저희가 만든 기준이 아니라 안산시 계획서 그대로입니다"라고 말할 수 있다.

| 공람안이 정한 것 | 쪽 | 우리 기능 |
|---|---|---|
| 6개월~1년 1회 현장 점검 | 14, 17 | **점검 기한 관리:** 빈집마다 다음 점검일을 계산하고, 기한이 지나면 색이 바뀐다 |
| 매달 4일 안전점검의 날 | 범정부·경기도 | **월간 점검 목록:** 매달 4일에 갈 곳 10~20개를 자동으로 뽑는다 |
| 협업 순찰 대상 조건 6개 | 18 | **우선순위 규칙:** 조건을 그대로 태그로 붙이고, 해당 개수로 순서를 정한다 |
| 점검 결과를 사진과 일지로 DB에 축적 | 17 | **사진 점검:** AI가 사진을 읽어 체크리스트와 일지 초안을 채우고, 담당자가 확인한다 |
| 안전조치 4부문(무단출입·범죄, 화재·설비, 위생·환경, 붕괴위험) | 14 | **체크리스트 항목:** 4부문을 그대로 쓴다 |
| 상태 악화 시 즉시 안전조치·철거로 전환 | 14, 17 | **악화 감지:** 이전 점검 사진과 비교해 새로 생긴 문제를 표시하고, 전환을 제안한다 |
| 민원 발생, 출입 흔적 확인 빈집 | 18 | **시민 제보:** 제보가 들어오면 그 빈집을 점검 목록 맨 앞으로 올린다 |
| 같은 다세대 건물 내 빈집 증가 | 18 | **건물 단위 묶기:** 같은 건물의 빈집 여러 호를 한 번에 본다 |
| 빈집정보시스템·빈집애 DB | 17 | **내보내기:** 점검 결과를 기존 DB 형식으로 넘긴다(대체하지 않음) |

## 3. 우선순위: 가중치 없이 규칙으로

| 순위(색) | 조건 | 근거 |
|---|---|---|
| **1순위 (빨강)** | 시민 신고가 접수됨(30일 안에 현장조사), 또는 최근 점검·제보에서 무단출입·화재·붕괴 신호가 확인됨 | 빈집법 시행령 제10조의3, 공람안 14쪽 |
| **2순위 (주황)** | 점검 기한이 다가왔거나 지남, 또는 공람안 18쪽 조건에 해당함 | 공람안 17·18쪽 |
| **3순위 (초록)** | 나머지. 1년 주기로 정기 점검 | 공람안 17쪽 |
| **회색** | 점검 기록이 아직 없음 | 첫 점검 대상 |

- **같은 순위 안에서는** 해당 조건이 많은 순, 그다음 기한을 넘긴 일수 순으로 정렬한다.
- 가중치를 임의로 정하지 않으니 "숫자를 왜 이렇게 잡았냐"는 질문이 생기지 않는다.

**지금 데이터로 계산해 본 규모** (위치는 근사값이라 [추정])

| 항목 | 값 |
|---|---|
| 점검 대상 | 144호 → 실제 방문지 약 116곳 |
| 같은 지번에 빈집 2호 이상 | 19곳, 47호 |
| 학교·어린이집·경로당 등 100m 이내 | 75호(약 절반) |
| 월 점검량 | 연 144~288회 → **월 12~24곳** |

생활시설 인접 조건 하나만으로도 절반이 해당한다. 그래서 조건 하나로 자르지 않고 **해당 개수로 순서를 정한다.**

## 4. AI가 하는 일 (담당자 일 줄이기)

| AI 역할 | 입력 → 출력 | 담당자가 하는 일 |
|---|---|---|
| 사진 판독 | 현장 사진 → 4부문 체크리스트, 18쪽 신호(출입 흔적, 창호 파손, 쓰레기, 우편물 누적, 공용부 관리 부실) | 틀린 항목만 고침 |
| 일지 초안 | 체크 결과 → 점검 일지 문단 | 확인 후 저장 |
| 악화 비교 | 이번 사진 + 이전 사진 → "새로 생긴 문제" 목록 | 전환할지 결정 |
| 제보 정리 | 시민 제보 → 같은 빈집·건물에 묶기, 긴급도 분류 | 확인 |

**AI는 판정하지 않는다.** 최종 판단은 언제나 담당자가 한다.

## 5. 신규 의심 빈집 지도(SOS)는 어디에

| 안 | 내용 |
|---|---|
| **(가) 보조 층으로 둔다 (권장)** | 등록 144호 밖의 건물에 안산판 SOS 점수를 매긴다. 2027년 특별법의 **매년 현황조사(제8조②) 대상 후보**로 지도에 옅게 보여 준다 |
| (나) 뺀다 | 등록 빈집과 시민 제보만으로 지도를 만든다. 가장 단순하다 |

(가)로 가면 지금까지 만든 지표 작업이 살아난다. 동시에 메인 이야기는 "상시관리 실행"으로 유지된다.

## 6. 5분 데모

| 단계 | 시간 | 화면 | 보여 줄 것 |
|---|---|---|---|
| 1 | 0:00~0:40 | 슬라이드 | 시가 정한 숙제(144호, 6개월~1년, 사진·일지, 순찰 조건) vs 공람본에 없는 것. 의회 지적, 업무분장 |
| 2 | 0:40~1:20 | 담당자 지도 | "11월 4일 안전점검의 날" 목록 15곳. 1위를 누르면 이유가 나옴(공람안 조건 태그 + 기한 초과 일수) |
| 3 | 1:20~1:50 | 시민 제보 (폰) | "문이 열려 있고 사람이 드나든 흔적" + 사진 → 그 빈집이 1순위로 올라가고 D-30 표시 |
| 4 | 1:50~2:50 | 현장 점검 (폰) | **라이브:** 사진을 찍으면 AI가 4부문 체크리스트와 일지 초안을 채움 → 담당자가 1개 수정 후 저장 |
| 5 | 2:50~3:30 | 빈집 기록 | 이전 사진과 비교해 "창호 파손 신규" 표시 → 무단출입·범죄 부문 1차 조치(창호 봉쇄) 전환 제안 |
| 6 | 3:30~4:10 | 빈집 기록 | 한 빈집의 제보·점검·조치가 시간순으로 쌓인 타임라인, 기존 DB 형식으로 내보내기 |
| 7 | 4:10~5:00 | 슬라이드 | 검증 숫자, 향후계획 |

**가장 강한 장면은 4~5단계다.** 사진 한 장이 일지가 되고, 지난 사진과 비교해 조치로 넘어간다.

## 7. 보여 줄 숫자 (실현가능성)

| 숫자 | 만드는 법 |
|---|---|

## 8. 향후계획 (슬라이드만)

1. 경찰·소방·동 행정복지센터 협업 순찰 화면(공람안 18쪽). 개별 위치는 공개하지 않고, 기관용으로만 제공한다(빈집법 제15조⑤⑥)
2. 신규 의심 빈집 지도를 매년 현황조사와 연계
3. 빈집정보시스템 API 연동
4. 2027년 특별법 전담조직의 표준 업무 도구로 확장

## 9. 팀이 정할 것

1. **신규 의심 빈집 지도(SOS):** 보조 층으로 둘지(권장), 뺄지
2. **우선순위:** 공람안 조건 규칙(권장)으로 할지, P×H×E 점수로 할지
3. **시범 구역:** 빈집이 많은 와동·부곡동·일동·선부동 중 1~2곳
4. **데모 사진:** 언제, 어디서, 몇 장 찍고 정답 판정은 누가 할지
5. **확인 전화 1통:** 빈집정보시스템에 재점검·사진 이력 기능이 있는지 (근거 문서 8장)
