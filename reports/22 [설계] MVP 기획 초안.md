# MVP 기획 초안 (방향성 확인용)

**원칙: 시연이 잘 보이는 게 전부다.** 아이디어 해커톤이라 기술 복잡도와 보안은 점수와 무관하다. 내부는 가짜여도 되고, 화면에서 "제보 → 우선순위 → 점검 → 지도 변화"가 끊기지 않고 보이면 된다.

## 1. 한 줄

시가 빈집을 판정·관리하는 데 필요한 현장 정보를 더 빨리, 더 많이, 기록으로 남게 모으는 도구. 빈집을 예측하지 않고 **현장조사 순서**를 정해 준다.

## 2. 5분 데모 시나리오 (MVP의 기준)

| 단계 | 화면 | 보여 줄 장면 |
|---|---|---|
| 1 | 슬라이드 | 158호 중 91%가 "지켜보는" 대상, 점검·기록 도구가 없음, 신고 30일 기한 |
| 2 | 담당자 지도 | 안산 지도 전체에 우선순위 그라데이션. 회색(미점검)이 많다. 1위를 누르면 "왜 1위인지" 점수 분해 카드 |
| 3 | 시민 제보 (폰) | "문이 열려 있고 쓰레기가 쌓였어요" + 사진 + 위치 |
| 4 | 담당자 지도 | 제보가 기존 빈집 기록에 자동으로 묶이고, D-30 배지와 함께 목록 상단으로 올라감. 시민 지도는 격자 색만 바뀜 |
| 5 | 현장점검 (폰) | **라이브:** 심사위원이 현장 사진을 찍으면 AI가 체크리스트를 채움 → "조치 필요" |
| 6 | 담당자 지도·빈집 기록 | **지도 색이 바뀌는 순간**, 한 빈집에 제보·점검이 시간순으로 쌓인 타임라인 |
| 7 | 빈집 기록 | 담당 부서 지정, 상태 "요청" |
| 8 | 슬라이드 | 검증 숫자(상위 10%만 봐도 등록 빈집 ○% 포착), 향후계획 |

**가장 강한 장면은 5~6단계**다. 사진 한 장이 지도와 순위를 바꾸는 순간은 무슨 일이 있어도 남긴다.

## 3. 만들 범위: 진짜 / 미리 만들어 둔 것 / 슬라이드

| 구분 | 내용 |
|---|---|
| **진짜로 동작** | 지도 그라데이션(실제 안산 건물·빈집 데이터), 점수 분해 카드, 시민 제보 입력, **AI 사진 판독(라이브 1회)**, 점검 후 색·순위·타임라인 갱신 |
| **미리 만들어 둔 것 (가짜 OK)** | 제보 묶기 결과, 기존 제보·점검 이력, 부서 지정 화면, AI 응답 캐시(라이브 실패 대비) |
| **슬라이드로만** | 순찰대 화면, 개인정보 가림, 로그인, 외부 데이터 연동, 기관 협업 |

## 4. 화면 3개

| 화면 | 기기 | 핵심 |
|---|---|---|
| 담당자 대시보드 | 노트북(프로젝터) | 왼쪽 지도, 오른쪽 우선순위 목록, 누르면 점수 분해·타임라인 |
| 시민 제보 | 폰 | 카테고리 버튼 → 사진 → 위치 → 제출 |
| 현장점검 | 폰 | 사진 → AI 체크리스트 → 판정 3택 |

화면 전환은 상단 역할 버튼으로 한다. 시민 지도(격자)는 대시보드의 토글로 대신한다.

## 5. 기술: 가장 빨리 예쁘게

| 부분 | 선택 |
|---|---|
| 화면 | 웹 페이지 하나(HTML + Leaflet 지도). 폰과 노트북이 같은 주소로 접속 |
| 데이터 | 해커톤 전에 파이썬으로 미리 계산한 GeoJSON(안산 주택·빈집·점수) |
| 서버 | 작은 파이썬 서버 하나(FastAPI). 제보·점검 저장과 AI 호출만 |
| AI | 멀티모달 LLM API로 사진 판독, JSON으로 받음. 시연 사진 응답은 미리 캐시 |
| 동기화 | 폰에서 저장하면 대시보드가 몇 초마다 새로 불러와 색이 바뀜 |

대안: 프론트를 만들 사람이 없으면 Streamlit 한 장. 대신 폰 화면이 투박해진다.

## 6. 데이터·점수 (MVP 간단 버전)

- **지금 바로 계산되는 지표:** 건물 연식(주택 중 결측 21동뿐), 최근접 등록 빈집 거리. 인구 감소는 파일만 받으면 바로 추가. 공시지가·정비구역은 못 받으면 "향후 추가"로 표시
- **점수:** 우선순위 = P(빈집 가능성: 지표 백분위의 평균) × H(위해: 빈집법 제11조 1호 > 2호 > 3·4호) × E(노출: 주변 주택 밀도) + 오래 미점검 가점. 신고 30일 기한 임박 건은 맨 앞
- **슬라이드에 넣을 검증 숫자 하나:** "점수 상위 10% 주택만 봐도 등록 빈집의 ○%가 들어 있다(무작위면 10%)"
- 숫자는 모두 초기값이다.

## 7. 마일스톤

| # | 언제 | 완료 기준 |
|---|---|---|
| M1 | 해커톤 전 | 안산 지도에 점수 그라데이션이 뜬다 |
| M2 | 해커톤 전 | 현장 사진 20~30장으로 AI 판독이 JSON으로 잘 나오고, 시연 사진 응답을 캐시했다 |
| M3 | 해커톤 중 | 폰 제보·점검 → 대시보드 색 변화까지 한 바퀴가 돈다 |
| M4 | 해커톤 중 | 시나리오를 네트워크 없이도 끝까지 재생할 수 있고, 녹화본이 있다 |

## 8. 팀이 정할 것

1. **시범 구역 1~2곳:** 지도를 어디 중심으로 보여 줄지. 빈집이 몰린 와동·부곡동·일동·선부동 중에서 고르는 걸 권장
2. **데모 사진:** 언제 어디서 몇 장 찍고, 정답 판정은 누가 할지
3. **화면 구성:** 웹 페이지(권장) vs Streamlit
4. **지표 마감:** 인구·공시지가·정비구역 파일을 언제까지 받고, 못 받으면 뺄지
5. **회색 빈집 처리:** 점검 이력이 없는 빈집을 얼마나 끌어올릴지(차별점 "신고 없는 곳도 관리"와 직결)
