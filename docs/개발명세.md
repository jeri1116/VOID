# VOID MVP 개발 명세서

> **버전:** v1.1 · 2026-11-08 (AI 초안 v1.0을 팀 확정 방향으로 고친 판)
> **팀:** 4명. 프론트(FE) 1 / 백엔드(BE) 1 / AI 1 / PPT·대본 1. AI·PPT 담당은 개발 경험이 없다. 코드는 Claude·Codex가 짜고, 사람은 설계·검토를 한다.
> **개발 시간:** 6시간
> **기술:** Next.js App Router + TypeScript + React Leaflet + Gemini API(무료, 예비 GPT-4o)
> **제약:** DB 없음. 상태는 메모리에 둔다. 노트북 localhost 한 대에서 시연한다.
> **화면:** `docs/와이어프레임.html`(확정)
> **원칙:** **시연이 잘 보이는 게 전부다.** 보안과 기술 복잡도는 점수와 무관하다. 6시간 안에 못 끝낼 기능은 스크린샷·목업으로 보낸다.

## 1. 프로젝트 정의와 완료 조건

**한 줄:** 안산시 등록 빈집 중 어디부터 가야 하는지 SOS 긴급도 지도로 보여 준다. 시민 제보 → 현장 사진 AI 판독 → 담당자 확정 → 조치 완료까지 한 빈집 기록에 남긴다.

**시연 시나리오 [확정]:** 발표는 PPT로 한다. 노트북에서 아래 장면을 부분적으로 보여 준다. **3·4번은 반드시 돈다.**

1. **담당자 지도(`/admin`):** 실제 공람안 빈집 158호를 방문지 130곳으로 묶어 SOS 색으로 표시한다. KPI 카드에 빨강 24곳 / 주황 65곳 / 초록 41곳이 나온다. "시가 위험하다고 판정한 24곳은 조치가 2027~2030년 예정이다. 그때까지 누가 보나?"
2. **시민 제보(`/report`):** 카테고리, 제목, 내용, 사진, 구역을 넣고 제출한다. `/admin` 지도에 **노란 시민 제보 구역**이 생기고, 30일 제보 목록 맨 위에 올라간다.
3. **현장 점검(`/admin` 상세 패널):** 빈집 선택 → 제보를 이 빈집에 연결 → 현장 사진 업로드 → AI가 5개 항목 관찰·단계 후보·일지 초안을 채운다(실패하면 캐시) → 담당자가 1단계로 확정 → **진한 빨강**, "봉쇄 필요"
4. **조치:** 조치 완료 사진을 올린다 → **초록**, 다음 점검은 6개월 뒤
5. **기록:** 상세 패널 타임라인에서 제보·점검·조치가 시간순으로 쌓인 것을 보여 준다.

**완료 조건(Definition of Done):**
1. `data/houses.json` 130곳 로딩, SOS 색, KPI 카드(24/65/41)
2. 먼저 갈 곳 목록, 점 클릭 시 상세 패널
3. `/report` 제보 → `/admin`의 노란 구역과 30일 목록 표시
4. 사진 업로드 → AI 판독(라이브 1회)과 캐시 폴백
5. 단계 확정·조치 완료 → 지도 색 갱신
6. 타임라인(가상 이력 + 시연 중 기록)

6시간 안에 1·2·4·5를 먼저 끝낸다.

**하지 않는 것:**
- 로그인·권한, 실제 민원 발송, 경찰·소방·동 협업 순찰, 빈집정보시스템 연동
- 사진 개인정보 가림, 개인 식별, 실제 건물 정확 주소 표시
- 신규(미등록) 빈집 예측, DB, 배포
- 현장 점검 전용 폰 화면(점검은 `/admin`에서 한다)
- '3개월 뒤' 버튼과 시간 시뮬레이션
- 이전 사진 비교(악화 감지)

이 중 순찰대·협업 순찰·시스템 연동·로그인·개인정보 가림은 PPT 스크린샷·목업으로만 보여 준다.

**앱이 읽는 데이터 파일은 `data/houses.json` 하나다.** 가공은 `scripts/build_houses.py`로 이미 끝났다. 6시간 안에 다시 가공하지 않는다.

| 파일 | 내용 | 쓰임 |
|---|---|---|
| **`data/houses.json`** | 방문지 130곳(158호). 같은 동 + 같은 가린 지번은 한 점 | **앱 입력** |
| `data/안산 빈집정비계획 공람안 빈집목록.csv` | 공람안 167호(계획대상 158 + 거주확인 제외 9) | `houses.json` 원천 |
| `data/안산 빈집 158호 위치 근사.csv` | 가린 지번으로 찾은 근사 좌표(EPSG:5186) | 원천 |
| `data/안산 건물 전체 (GIS건물통합정보 202610).csv` | 건물 72,171동(용도, 사용승인일, 좌표). 대용량이라 git 제외 | 피해 범위 계산 |
| `data/안산 주택 최근접빈집거리.csv` | 주택 23,723동 | 피해 범위(주택 밀도) 계산 |

**`houses.json` 한 항목**
```json
{
  "id": "선부동-1089-1**", "dong": "선부동", "jibun": "1089-1**",
  "lat": 37.3455, "lng": 126.8154,
  "units": 4, "codes": ["16588670", "..."], "types": ["다세대"], "grade": 1,
  "plan": "안전조치", "planYear": "29",
  "exposure": { "facility": true, "cluster": true, "density": true }, "exposureCount": 3,
  "cycleMonths": 6, "lastChecked": "2026-01-01",
  "hazardStage": "시판정", "actionDone": false,
  "timeline": [{ "date": "2025-12-31", "type": "실태조사", "note": "시 판정 1등급, 정비방식 안전조치" }]
}
```

**사실과 가정**
- **실제:** 158호 목록, 유형·등급·정비방식, 방문지 묶음, 피해 범위 3조건(실제 건물 데이터로 계산)
- **근사:** 위경도. 가린 지번 후보 건물의 좌표 평균이고, 오차 중앙값은 39m다. 정확한 위치라고 말하지 않는다.
- **가정:** `lastChecked: 2026-01-01`(점검 이력이 없어서 넣은 값), 타임라인 첫 줄 날짜
- **좌표계:** EPSG:5186으로 확인했고, 변환을 검증했다(선부동 37.346, 126.815).
- **144호:** 상시관리 123 + 안전조치 21이다. `plan`으로 바로 구분된다. 지도에는 158호(130곳) 전체를 보여 준다.

**시연용 추가 데이터(`fixtures/`)**
- `initial-events.json`: 미리 넣은 제보 3~5건, 일부 빈집의 가상 점검 이력. 지도 색을 다양하게 보이려는 용도다.
- `ai-cache.json`: 시연 사진의 AI 응답과 기본 응답 1건
- `demo-images/`: 시연 사진 3~5장

**단위:** `site` = 방문지 1곳(지도 점 130개), `report` = 제보 1건, `zone` = 시민 제보 구역(250m 격자). 호(158) 단위 화면은 만들지 않는다. 상세 패널에는 `units`(호 수)와 `codes`만 보여 준다.

## 3. SOS 긴급도 규칙

> **SOS는 등록 빈집 그 자체의 긴급도다.** 주변 지역 위험지수가 아니다.
> 가중치, 가중합, 곱셈, 0~100 점수를 쓰지 않는다. **AI가 색을 정하지 않는다.**
> 와이어프레임의 "우선순위 점수(0~100)" 표기는 **SOS 색과 "왜 이 색인지" 이유**로 바꾼다.

### 3.1 피해 범위 조건 (0~3개, `houses.json`에 계산돼 있음)

1. 반경 100m 안에 교육연구시설 또는 노유자시설이 있다 (`exposure.facility`)
2. 같은 지번에 빈집이 2호 이상이거나, 100m 안에 다른 등록 빈집이 있다 (`exposure.cluster`)
3. 반경 100m 안 주택 수가 시 중앙값(44동) 이상이다 (`exposure.density`)

### 3.2 점검 주기 (`cycleMonths`, `houses.json`에 계산돼 있음)

- **6개월:** 유형이 단독·그외, 또는 시 등급 2·3, 또는 피해 범위 조건 2개 이상
- **12개월:** 그 외
- **조치 완료 직후에는 6개월로 바꾼다.**
- 다음 점검일 = `lastChecked` + `cycleMonths`(달 단위로 더함)
- **기준일은 서버 상수 `2026-11-08`이다.** 바꾸는 기능은 없다.

### 3.3 지도 점 색 (4단계)

| 색 | 조건 | 할 일 |
|---|---|---|
| **진한 빨강** `DARK_RED` | 점검에서 1단계(붕괴·화재·범죄 우려) 확정, 아직 조치 안 함 | 조치 |
| **빨강** `RED` | 점검에서 2단계(위생) 확정, 또는 시 정비방식이 안전조치·철거인데 아직 조치 전 | 조치·상태 확인 |
| **주황** `ORANGE` | 점검에서 3단계(경관·생활환경) 확정, 또는 다음 점검일이 지남 | 확인 |
| **초록** `GREEN` | 기한 안에 확인했고 이상 없음, 또는 조치 완료 | — |

- **합성:** 위해 판정과 기한 중 더 나쁜 쪽을 따른다.
- **`houses.json`의 `hazardStage: "시판정"` 해석:** 정비방식이 안전조치·철거라는 뜻이다. 앱에서는 `cityPending = true`(빨강 최소)로 읽는다. 점검에서 확정한 단계는 `hazardStage`(1·2·3·null)에 따로 둔다.
- **조치 완료(`actionDone = true`):** 위해 단계와 `cityPending`을 해소로 보고 초록으로 바꾼다. 다음 점검은 완료일 + 6개월이다. 조치 완료 전에는 확인된 위해 색을 유지한다.
- **시연 주의:** 조치 장면은 **주황 빈집**에서 시작한다. 시가 판정한 빨강 빈집을 봉쇄 한 번으로 초록으로 만들면 "철거 계획이 끝난 것"처럼 보이기 때문이다.
- **정렬:** 색이 나쁜 순 → 피해 범위 개수 많은 순 → 기한 넘긴 일수 많은 순 → `id` 순
- **시작 상태(기준일 2026-11-08):** 빨강 24 / 주황 65 / 초록 41. `build_houses.py`로 재현을 확인했다.

### 3.4 노랑 = 시민 제보 구역

- 시민이 `/report`에서 고른 **250m 격자 구역**을 `/admin` 지도에 **노란 반투명 사각형**으로 표시한다. 범례 이름은 "시민 제보 구역"이다.
- 제보 하나에 기한(**접수일 + 30일**, 빈집법 시행령 제10조의3)이 붙는다. 30일 제보 목록은 기한이 가까운 순으로 정렬한다.
- 담당자가 구역 안의 빈집과 연결하면, 그 빈집 점에 **D-day 배지**가 붙고 타임라인에 기록된다.
- **제보는 빈집 점의 색을 바꾸지 않는다.** 색은 현장 점검에서 확정한 결과로만 바뀐다.
- 구역 안에 등록 빈집이 없으면 "미등록 확인 요청"으로 분류한다. 지도 색 집계에는 넣지 않는다.

### 3.5 SOS 함수 계약

```ts
export type SosColor = 'DARK_RED' | 'RED' | 'ORANGE' | 'GREEN';
export type HazardStage = 1 | 2 | 3 | null;   // 점검 확정 단계. null = 이상 없음 또는 미점검

export interface SosInput {
  exposureCount: number;     // 0..3
  cycleMonths: 6 | 12;
  lastChecked: string;       // YYYY-MM-DD
  hazardStage: HazardStage;
  cityPending: boolean;      // 정비방식 안전조치·철거이고 아직 조치 전
  actionDone: boolean;
  asOf: string;              // '2026-11-08' 고정
}

export interface SosResult {
  color: SosColor;
  nextInspectionAt: string;  // lastChecked + cycleMonths
  overdueDays: number;       // 기한 전이면 0
  reasons: string[];         // 상세 패널 "왜 이 색인지"
}

export function calculateSos(input: SosInput): SosResult;
```

## 4. 아키텍처와 저장

```text
Browser (Next.js pages)
  ├─ /          메인 홈: 서비스 소개, 유형 카드 3개
  ├─ /report    시민 제보(모바일): 카테고리·제목·내용·사진·구역 선택 → 접수 완료. 빈집 마커 없음
  ├─ /admin     시 담당자(데스크톱): KPI, 지도, 목록 탭, 상세 패널 4단계
  └─ /patrol    순찰대: 스크린샷 3장만
            |
            v
Next.js Route Handlers (Node.js runtime)
  ├─ GET /api/sites, GET /api/sites/[id]
  ├─ GET/POST /api/reports, PATCH /api/reports/[id]
  ├─ POST /api/ai/analyze
  ├─ POST /api/inspections
  └─ POST /api/actions
            |
            +-- src/lib/store.ts   메모리 상태(globalThis)
            +-- src/lib/sos.ts     색 계산
            +-- src/lib/ai/        Gemini 호출, 캐시 폴백
            +-- data/houses.json   (read-only)
            +-- fixtures/          initial-events.json, ai-cache.json, demo-images/
            +-- data/runtime/uploads/  (업로드 사진, .gitignore)
```

- **저장:** 서버가 시작할 때 `houses.json`과 `fixtures/initial-events.json`을 읽어 메모리에 둔다. 제보·연결·점검·조치는 메모리 상태를 바로 고치고, 타임라인에 한 줄을 붙인다.
- **globalThis:** 메모리 상태는 `globalThis`에 둔다. 그래야 라우트끼리 같은 상태를 보고, `next dev` 핫 리로드에도 남는다.
- **리셋:** 서버를 다시 켜면 처음 상태로 돌아간다. 이것을 리셋으로 쓴다.
- **사진:** 받은 그대로 `data/runtime/uploads/`에 둔다. 크기·형식 검사는 생략한다.
- **API 키:** **서버 전용 환경변수**에 둔다. 프론트로 노출하지 않는다.
- **AI 실패:** 오류를 내지 않고 캐시로 응답한다(`source: "CACHE"`).

## 5. 공통 타입 (`src/types/contracts.ts`)

```ts
export interface Site {            // houses.json 한 항목 + 계산값
  id: string; dong: string; jibun: string;
  lat: number; lng: number;        // 근사
  units: number; codes: string[]; types: string[]; grade: number;
  plan: string; planYear: string;
  exposure: { facility: boolean; cluster: boolean; density: boolean };
  exposureCount: number;
  cycleMonths: 6 | 12; lastChecked: string;
  hazardStage: HazardStage; cityPending: boolean; actionDone: boolean;
  sos: SosResult;
  openReportDueAt: string | null;  // 연결된 미종결 제보 중 가장 가까운 기한
  timeline: TimelineItem[];
}

export interface Zone { id: string; label: string; bounds: [[number, number], [number, number]] }

export type ReportCategory = '붕괴 위험' | '쓰레기 방치' | '무단 침입' | '화재 위험' | '해충·악취' | '기타';
export interface Report {
  id: string; category: ReportCategory; title: string; description: string;
  photoUrls: string[]; zone: Zone; createdAt: string; dueAt: string;   // createdAt + 30일
  status: 'OPEN' | 'LINKED' | 'UNREGISTERED';
  siteId: string | null; candidateSiteIds: string[];                    // 담당자 화면에서만 보임
}

export type ObsStatus = 'DETECTED' | 'NOT_DETECTED' | 'UNKNOWN';
export interface AnalysisResult {
  source: 'LIVE' | 'CACHE';
  observations: Record<'security' | 'fire' | 'hygiene' | 'collapse' | 'landscape', { status: ObsStatus; evidence: string }>;
  suggestedStage: 1 | 2 | 3 | null;
  draftJournal: string; recommendedAction: string | null;
}

export interface TimelineItem { date: string; type: '실태조사' | '제보' | '제보 연결' | '점검' | '조치 완료'; note: string }
```

## 6. API

**공통:**
- 성공 응답은 JSON이다. 오류는 `{ "error": { "code": "...", "message": "..." } }`로 보낸다.
- 오류 코드는 400(입력 오류)과 404(대상 없음)만 쓴다.
- 사진이 포함된 요청은 `multipart/form-data`로 받는다.

| # | Method | Endpoint | 담당 | 용도 |
|---|---|---|---|---|
| 1 | GET | `/api/sites` | BE | 130곳, 색, D-day, KPI 요약, 시민 제보 구역 목록 |
| 2 | GET | `/api/sites/[id]` | BE | 상세: SOS 이유, 정비방식, 다음 점검일, 피해 범위, 연결된 제보, 타임라인 |
| 3 | GET | `/api/reports` | BE | 담당자용 제보 목록(30일 기한순), 미등록 확인 요청 |
| 4 | POST | `/api/reports` | BE | 시민 제보 등록(구역 단위) |
| 5 | PATCH | `/api/reports/[id]` | BE | 담당자가 빈집에 연결하거나 미등록으로 분류 |
| 6 | POST | `/api/ai/analyze` | BE(+AI 프롬프트) | 사진 판독, 일지 초안 |
| 7 | POST | `/api/inspections` | BE | 위해 단계 확정 → 색 갱신 |
| 8 | POST | `/api/actions` | BE | 조치 완료 → 초록, 주기 6개월 |

### 6.1 `GET /api/sites`
```json
{
  "asOf": "2026-11-08",
  "summary": { "houses": 158, "sites": 130, "byColor": { "DARK_RED": 0, "RED": 24, "ORANGE": 65, "GREEN": 41 }, "openReports": 3 },
  "sites": [{ "id": "선부동-1089-1**", "lat": 37.3455, "lng": 126.8154, "color": "RED", "exposureCount": 3, "overdueDays": 0, "dDay": null }],
  "zones": [{ "id": "Z-0412", "label": "선부동 일대 250m 구역", "bounds": [[37.344, 126.814], [37.346, 126.817]], "openReports": 1 }]
}
```

### 6.2 `GET /api/sites/[id]`
`Site` 전체(5장)와 이 빈집에 연결된 `Report[]`를 돌려준다.

### 6.3 `GET /api/reports`
제보 목록이다. `OPEN`·`LINKED`는 `dueAt` 오름차순으로, `UNREGISTERED`는 따로 묶어 돌려준다. 각 제보의 `candidateSiteIds`(구역 안 등록 빈집)는 이 담당자 응답에만 넣는다.

### 6.4 `POST /api/reports`
- **Request(`multipart/form-data`):** `category`, `title`, `description`, `images`(0~3장), `lat`, `lng`
  - `lat`·`lng`는 시민이 지도에 찍은 점이다. 서버가 이 점을 250m 격자로 바꿔 `zone`으로 저장하고, 원래 좌표는 버린다.
- **Response `201`:** `{ "reportId": "R-2026-0001", "zoneLabel": "선부동 일대 250m 구역", "status": "OPEN" }`
  - 시민 화면에는 접수번호, 구역, 처리 단계만 보여 준다.
  - **후보 빈집은 이 응답에 넣지 않는다.**
  - 접수만으로는 SOS 색이 바뀌지 않는다.

### 6.5 `PATCH /api/reports/[id]`
- `{ "decision": "LINK", "siteId": "선부동-1089-1**" }`이면 `status = LINKED`로 바꾸고, 그 빈집에 D-day 배지와 타임라인 기록을 남긴다.
- `{ "decision": "UNREGISTERED" }`이면 미등록 확인 요청 목록으로 옮긴다.
- 같은 구역이라는 이유만으로 자동 연결하지 않는다. 확정 버튼은 담당자가 누른다.

### 6.6 `POST /api/ai/analyze`
**Request:** `multipart/form-data`. `image`(필수), `siteId`(필수)
**Response `200`:**
```json
{
  "source": "LIVE",
  "observations": {
    "security":  { "status": "DETECTED",     "evidence": "출입문 개방 흔적" },
    "fire":      { "status": "UNKNOWN",      "evidence": "설비 상태 확인 불가" },
    "hygiene":   { "status": "NOT_DETECTED", "evidence": "가시적인 쓰레기 없음" },
    "collapse":  { "status": "UNKNOWN",      "evidence": "내부 구조 확인 불가" },
    "landscape": { "status": "NOT_DETECTED", "evidence": "특이사항 없음" }
  },
  "suggestedStage": 1,
  "draftJournal": "출입문 개방 흔적이 관찰되어 출입 통제 검토가 필요함.",
  "recommendedAction": "출입구 봉쇄"
}
```
- 사진에 안 보이는 항목은 `UNKNOWN`으로 둔다. 안 찍혔다고 "위험 없음"으로 판단하지 않는다.
- 공람안 점검 4부문(보안·화재·위생·붕괴)에 경관·생활환경을 더해, 빈집법 제11조 3단계까지 대응한다.
- 응답은 `JSON.parse`로 읽은 뒤 5개 항목과 `suggestedStage`가 있는지만 확인한다. 호출이나 파싱이 실패하면 **바로 캐시로 응답한다**(`source: "CACHE"`).

### 6.7 `POST /api/inspections`
- **Request:** `{ "siteId": "...", "confirmedStage": 1, "journal": "무단출입 우려 확인. 출입구 봉쇄 필요." }`
  - `confirmedStage: null`은 "이상 없음"이다.
- **처리:** 서버가 메모리 상태를 고친다.
  - `hazardStage` = 확정한 단계
  - `lastChecked` = 오늘
  - `actionDone` = false
  - 타임라인에 한 줄 붙인다.
- **Response `201`:** `{ "siteId": "...", "color": "DARK_RED", "actionRequired": true }`
- 와이어프레임 패널 4단계의 "점수·상태 갱신"은 **위해 단계 선택(1·2·3단계 / 이상 없음) + 일지 + 저장**으로 바꾼다.

### 6.8 `POST /api/actions`
- **Request(`multipart/form-data`):** `siteId`, `completionImage`, `note`
- **처리:** 메모리 상태를 이렇게 바꾼다.
  - `actionDone` = true
  - `hazardStage` = null
  - `cityPending` = false
  - `cycleMonths` = 6
  - `lastChecked` = 오늘
  - 타임라인에 한 줄 붙인다.
- **Response `201`:** `{ "siteId": "...", "color": "GREEN", "nextInspectionAt": "2027-05-08" }`

## 7. AI

### 7.1 사진 분석: `src/lib/ai/analyze.ts` (Gemini, 예비 GPT-4o)

**프롬프트 조건**
- 사진에 **보이는 사실만** 쓴다.
- 보안·화재·위생·붕괴·경관 5개 항목을 각각 `DETECTED / NOT_DETECTED / UNKNOWN`으로 분류하고, 근거를 짧게 단다.
- 위해 단계는 후보만 낸다.
  - 보안·화재·붕괴 → 1단계
  - 위생 → 2단계
  - 경관 → 3단계
  - 확인 불가 → `null`
  - 여러 개가 해당하면 가장 심한 단계를 낸다.
- 일지는 1~3문장으로 쓴다. 조치 권고는 선택이다.
- 법적 확정이나 안전 보장 표현은 쓰지 않는다. JSON 외 텍스트는 쓰지 않는다.

**Gemini 호출:** JSON 출력 모드(`responseMimeType: application/json`)를 쓴다.

### 7.2 제보 후보 찾기: `src/lib/ai/match.ts` (AI 없이 규칙으로)

- **후보:** 제보 구역(250m 격자) 안의 등록 빈집. 없으면 바로 옆 8칸까지 본다. 그래도 없으면 후보 없음이다.
- **보여 주는 곳:** 후보는 담당자 화면에만 보여 준다. 연결은 담당자가 확정한다.
- **사진의 역할:** 사진으로 특정 집을 확정하지 않는다.

### 7.3 시연 사진과 캐시

- **시연 사진:** 3~5장. 그중 3장은 AI 응답을 `fixtures/ai-cache.json`에 저장해 둔다. 맞는 캐시가 없으면 기본 응답 1건을 돌려준다.
- **촬영 기준:** 공공도로에서 외관만 찍은 사진, 또는 사용 권한이 있는 자료만 쓴다. 얼굴·차량번호·정확한 주소가 나오지 않게 한다.
- **일치율:** 시간이 남으면 사진 20~30장으로 AI 판독과 팀 판정의 일치율을 잰다. 정확도를 말할 때는 사진 수와 계산 방법을 함께 밝힌다.
- **캐시 표시:** 캐시 응답은 LIVE라고 표시하지 않는다.
