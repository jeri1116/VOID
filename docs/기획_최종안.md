## 1. 한 줄 요약과 슬로건

### 한 줄 요약

**안산시 빈집정비계획(2026~2030, 주민공람안)이 정한 등록 빈집 정기 점검을 실제로 돌리는 도구.**

| 구성 | 내용 |
|---|---|
| 대상 | 공람안이 정기 점검하기로 한 **144호** (상시관리 123 + 안전조치 21). 6개월~1년마다, 사진·일지로 기록 |
| 어디부터 | **SOS 긴급도 지도**가 먼저 갈 곳을 보여 준다 |
| 어떻게 기록 | 시민 제보 → 현장 사진 AI 판독 → 담당자 확정 → 조치 완료를 **한 빈집 기록**에 남긴다 |

### 슬로건 후보

1. **"위험한 빈집부터, 정해진 주기대로"**
2. **"시가 정한 점검, 빠짐없이 돌게"**
3. **"빈집이 보내는 SOS, 기록으로 답합니다"**

### 우리 서비스를 한 문장으로 말할 때

> "데이터가 먼저 갈 곳을 제안하고, AI가 사진 관찰 초안을 쓰고, 담당자가 위해 단계와 조치 완료를 확정합니다."

## 2. 문제 정의

**핵심 문장: "주기는 정해졌는데, 방법·도구·기록 기준이 없다."**

> 주의: "도구가 없다", "DB가 없다", "주기가 없다"고 말하지 않는다. 공람안 17쪽이 빈집정보시스템·빈집애 DB를 명시했고, 주기(6개월~1년)도 정했다.

## 4. 해결안

### 4-1. 서비스 구조

```text
[시민 /report]  제보(카테고리·사진·250m 구역) ── 빈집 위치는 안 보임
        │
        ▼
[담당자 /admin]  SOS 긴급도 지도 + 노란 제보 구역 + KPI + 먼저 갈 곳 목록
        │  ① 빈집 선택 · 구역 안 후보 빈집에 제보 연결 (담당자가 확정)
        │  ② 현장 사진 업로드
        │  ③ AI 판독: 5개 항목 관찰 + 위해 단계 후보 + 일지 초안
        │  ④ 담당자가 위해 단계 확정 → 색 갱신 → 조치 완료 사진 → 초록, 6개월 뒤 점검
        ▼
[한 빈집 기록]  실태조사 → 제보 → 제보 연결 → 점검 → 조치 완료 (타임라인)
```

| 화면 | 사용자 | 하는 일 | MVP |
|---|---|---|---|
| `/` | 누구나 | 서비스 소개, 유형 카드 3개 | 구현 |
| `/report` | 시민(모바일) | 카테고리·제목·내용·사진(최대 3장)·구역 선택 → 접수번호·구역·처리 단계 확인. **빈집 마커와 건물 정보 없음** | 구현 |
| `/admin` | 시 담당자(데스크톱) | KPI 카드, 4색 지도, 노란 제보 구역, 목록 탭(먼저 갈 곳 / 30일 제보 / 미등록 확인 요청), 상세 패널 4단계 | 구현 |
| `/patrol` | 협업 순찰 | 스크린샷 3장만 | **향후계획** |

**우리가 하지 않는 것:** 새 빈집 예측, 빈집 판정, 부동산 거래·활용, 기존 DB 대체.

### 4-2. SOS 긴급도 규칙

**SOS = 등록 빈집 그 자체의 긴급도.** 주변 지역의 위험지수가 아니다. **가중치·점수·곱셈이 없다.**

**두 가지 위험**

| 위험 | 뜻 | 근거 |
|---|---|---|
| **확인된 위험** | 위해 단계. 빈집법 제11조 1~4호. 시 판정(정비방식 안전조치·철거) 또는 점검에서 담당자가 확정 | 현행 빈집법 제11조 ①항, 공람안 11·14쪽 |
| **모르는 위험** | 점검 기한이 지나 지금 상태를 모름. 주기는 **6개월 또는 12개월** | 공람안 14·17쪽 "6개월~1년" |

**두 위험 중 더 나쁜 쪽이 색이 된다.**

**색 4단계 + 노랑**

| 색 | 조건 | 할 일 |
|---|---|---|
| **진한 빨강** | 점검에서 **1단계**(붕괴·화재·범죄 우려, 제11조 1호) 확정, 아직 조치 전 | 조치 |
| **빨강** | 점검에서 **2단계**(위생, 2호) 확정, 또는 **시가 안전조치·철거로 판정**했는데 아직 조치 전 | 조치·상태 확인 |
| **주황** | 점검에서 **3단계**(경관·생활환경, 3·4호) 확정, 또는 **점검 기한이 지남** | 확인 |
| **초록** | 기한 안에 확인했고 이상 없음, 또는 조치 완료 | — |
| **노랑(구역)** | **시민 제보 구역.** 250m 격자. 접수 후 30일 안에 현장조사(시행령 제10조의3) | 30일 안 현장조사 |

- **노랑은 빈집 점이 아니라 구역이다.** 제보는 빈집 점의 색을 바꾸지 않는다. 색은 현장 점검 확정으로만 바뀐다.
- 담당자가 제보를 구역 안 빈집에 연결하면 그 점에 **D-day 배지**가 붙는다.
- 구역 안에 등록 빈집이 없으면 "미등록 확인 요청"으로 따로 둔다. 빈집인지는 시가 판정한다.

**점검 주기**

| 조건 | 주기 |
|---|---|
| 하나라도 해당: 유형 단독·그외 / 시 등급 2·3 / 피해 범위 조건 2개 이상 / 조치 완료 직후 | **6개월** |
| 그 외 | **12개월** |

**피해 범위 조건 3개** (공람안 18쪽 순찰 대상 조건에서 왔다. 개수 0~3을 센다)

| # | 조건 | 공람안 18쪽 대응 |
|---|---|---|
| 1 | 반경 100m 안에 교육연구시설·노유자시설이 있다 | ③ 학교·어린이집·경로당 등 생활시설 인접 |
| 2 | 같은 지번에 빈집 2호 이상, 또는 100m 안에 다른 등록 빈집 | ④ 동일 다세대·연립 건물 내 빈집 증가 |
| 3 | 반경 100m 안 주택 수가 시 중앙값(44동) 이상 | 주택 밀집(노출) |

- **쓰는 곳 두 군데:** ① 점검 주기(2개 이상이면 6개월) ② 같은 색 안의 순서
- **정렬:** 색이 나쁜 순 → 피해 범위 개수 많은 순 → 기한 넘긴 날수 많은 순

**방어 근거**

| 질문 | 근거 | 태그 |

### 4-3. AI의 역할과 한계

| 항목 | 내용 |
|---|---|
| 모델 | Gemini (JSON 출력 모드). 예비 GPT-4o. 실패하면 저장해 둔 응답(캐시)으로 보여 주고 "캐시"라고 표시 |
| 입력 | 현장 사진 1장 + 빈집 ID |
| 관찰 5개 항목 | **보안**(출입 흔적, 문·창 개방·파손) / **화재**(인화물, 설비 이상) / **위생**(쓰레기, 악취·해충 흔적) / **붕괴**(균열, 지붕·벽 붕괴) / **경관**(잡초, 외벽 훼손, 우편물 누적) |
| 항목별 결과 | 발견 / 발견 안 됨 / **확인 불가** + 짧은 근거 |
| 단계 후보 | 보안·화재·붕괴 → 1단계, 위생 → 2단계, 경관 → 3단계, 확인 불가 → 없음. 여럿이면 가장 심한 단계 |
| 일지 초안 | 1~3문장 + 조치 권고(선택). 공람안 17쪽 "사진과 일지"를 채운다 |
| 항목의 근거 | 공람안 14쪽 안전조치 4부문(무단출입·범죄, 화재·설비, 위생·환경, 붕괴위험) + 제11조 3·4호 대응 경관 |

**AI가 하지 않는 것**
- **AI는 색을 정하지 않는다. 확정은 담당자가 한다.**
- 사진에 안 보이면 "확인 불가"로 둔다. "위험 없음"으로 판단하지 않는다.
- 법적 확정·안전 보장 표현을 쓰지 않는다.
- 사진으로 특정 집을 찾지 않는다. 제보와 빈집 연결도 담당자가 확정한다.
- 외관만 본다. 내부 설비(시행령 제8조의2 2호)는 시 담당자 출입 조사 몫이다.

**정확도:** AI 판독과 팀 판정의 **일치율은 "측정 예정"**이다. 사진 20~30장으로 잴 계획이다. 발표할 때는 사진 수와 계산 방법을 같이 밝힌다.

## 11. 슬라이드 구성안 (12장)

| # | 제목 | 핵심 메시지 한 줄 | 들어갈 재료 |
|---|---|---|---|
| 1 | VOID — 위험한 빈집부터, 정해진 주기대로 | 안산시가 정한 빈집 정기 점검을 실제로 돌리는 도구 | 슬로건, 한 줄 요약 |
| 2 | 안산은 빠르게 늙고, 빠져나가고 있다 | 인구 −15.1%(15년), 30년 넘은 주택 37% → 68%(9년) | 3-1, 3-2 |
| 3 | 빈집은 적지만 몰려 있다 | 158호, 4개 동에 44%, 다세대 79% — 적을 때 관리한다 | 3-3, 반론 선제 차단 |
| 4 | 시가 이미 정한 숙제 | 144호를 6개월~1년마다 점검하고 사진·일지로 남긴다(공람안 11·14·17쪽) | 2-2 |
| 5 | 주기는 있는데, 방법이 없다 | 누가·어디부터·어떤 기준으로가 공람본에 없다 | 2-3 표, 시의회 2024, 국토연 이력관리 |
| 6 | 위험 판정 24곳, 그때까지 누가 보나 | 시가 위험하다고 본 24곳 대부분은 조치가 2027~2030년 | 6-1 지도 캡처(빨강 24) |
| 7 | VOID의 흐름 | 제보 → 사진 AI 판독 → 담당자 확정 → 조치 → 한 빈집 기록 | 4-1 구조도 |
| 8 | SOS 긴급도: 점수 없이 법과 계획으로 | 확인된 위험과 모르는 위험 중 더 나쁜 쪽이 색 | 4-2 색 표, 방어 근거 |
| 9 | AI는 초안, 확정은 사람 | 5개 항목 관찰 + 단계 후보 + 일지 초안. 색은 담당자가 정한다 | 4-3, 상세 패널 캡처 |
| 10 | 시연 | 빨강 24 → 노란 제보 구역 → AI 판독 → 진한 빨강 → 초록 → 타임라인 | 6-3 (라이브, 실패 시 녹화본) |
| 11 | 판정 전이 아니라 판정 후 | 다른 도구는 "어디가 빈집인가", 우리는 "확정 빈집이 지금 어떤가" | 5장 비교 표 |
| 12 | 실현가능성과 다음 단계 | 실제 158호·130곳으로 구현. 다음은 협업 순찰·DB 연동·2027 전담조직 | 6-2, 7장 지표, 8장 |

**발표 순서 팁**
- 2~3장에서 "빈집 수가 적다"를 먼저 막는다.
- 4~5장은 "시가 정한 숙제 → 비어 있는 실행 수단" 순서로, 시를 비판하지 않고 "시의 약속을 돕는다"는 톤을 유지한다.
- 6장 질문으로 시연에 들어간다.
- 마지막 문장 예시: "안산시는 이미 무엇을 할지 정했습니다. 저희는 그 계획이 매달, 매 집마다 실제로 돌게 하겠습니다."
