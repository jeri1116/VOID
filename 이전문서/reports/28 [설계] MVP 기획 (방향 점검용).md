# MVP 기획 (방향 점검용)

> 기준 문서: `27`(SOS 긴급도 규칙, 확정), `25`(솔루션 계획), `24`·`26`(근거). 이 문서는 `22`번 MVP 초안을 대체한다.
> 원칙: **시연이 잘 보이는 게 전부다.** 아이디어 해커톤이라 내부는 가짜여도 된다. 보안과 기술 복잡도는 점수와 무관하다.

---

## 1. 한 줄

안산시가 정한 빈집 144호 정기 점검을 돌리는 도구다. 지도는 **어디부터 갈지**(SOS 긴급도)를 보여 주고, 사진 한 장으로 **점검 기록**을 남기고, 위험하면 **조치로 넘긴다.**

## 2. 5분 시연

| # | 화면 | 장면 |
|---|---|---|
| 1 | 슬라이드 | 시가 정한 숙제(144호, 6개월~1년 점검, 사진·일지)와 공람본에 없는 것(누가, 어디부터, 어떻게) |
| 2 | 담당자 지도 | 첫 지도. **빨강 24곳**: 시가 위험하다고 판정했지만 조치는 2027~2030년 예정인 곳. "그때까지 누가 보나?" |
| 3 | 시민 제보 (폰) | 기존 빈집에 출입 흔적 제보 → 그 빈집 기록에 연결 → **30일 기한 목록** 맨 위에 올라감 |
| 4 | 현장 점검 (폰) | **라이브:** 사진 → AI가 4부문 체크리스트와 일지 초안을 채움 → 담당자가 1단계로 확정 → **진한 빨강**, "봉쇄 필요" |
| 5 | 현장 점검 (폰) | 봉쇄 완료 사진 → **초록**, 다음 점검 6개월 뒤 |
| 6 | 빈집 기록 | 제보·점검·조치가 시간순으로 쌓인 타임라인. "3개월 뒤" 버튼을 누르면 지도가 서서히 진해짐 |
| 7 | 슬라이드 | 검증 숫자, 향후계획 |

**가장 강한 장면은 4~5번이다.** 사진이 위험을 잡아내고, 조치가 끝나야 초록이 된다.

## 3. 화면 3개

| 화면 | 기기 | 핵심 |
|---|---|---|
| 담당자 대시보드 | 노트북 | 왼쪽은 SOS 긴급도 지도, 오른쪽은 탭 3개(먼저 갈 곳 / 30일 제보 / 미등록 확인 요청). 점을 누르면 "왜 이 색인지"와 타임라인이 나옴 |
| 현장 점검 | 폰 | 사진 → AI 체크리스트·일지 초안 → 단계 확정(1·2·3단계 / 이상 없음) → 조치 요청 또는 조치 완료 |
| 시민 제보 | 폰 | 사진·글·위치 → 접수번호. 긴급하면 112·119 안내 |

## 4. 범위

| 구분 | 내용 |
|---|---|
| **진짜로 동작** | 158호 실제 데이터로 그린 지도, 27번 색 규칙 계산, 사진 AI 판독(라이브 1회), 점검·조치 후 색 갱신, 제보 → 기존 빈집 연결 |
| **미리 만들어 둠 (가짜 OK)** | 가상 점검 이력(색을 다양하게 보이려고), 기존 제보 몇 건, AI 응답 캐시(라이브 실패 대비) |
| **슬라이드로만** | 경찰·소방·동 협업 순찰, 빈집정보시스템 연동, 2027년 특별법 전담조직, 로그인, 사진 개인정보 가림 |

## 5. AI가 하는 일 (딱 2개)

| 역할 | 입력 → 출력 |
|---|---|
| 사진 판독 | 현장·제보 사진 → 4부문 체크(무단출입·범죄 / 화재·설비 / 위생·환경 / 붕괴) + 위해 단계 후보 + 일지 초안 |
| 제보 연결 | 제보 위치·사진 → 같은 빈집 후보 제시(같은 지번 또는 근접), 없으면 미등록 확인 요청 |

AI는 후보만 낸다. 확정은 담당자가 한다.

## 6. 데이터와 기술

- **데이터**
  - 공람안 158호 목록과 근사 위치
  - 건물 데이터(피해 범위 3조건 계산)
  - 시연 사진 20~30장(공공도로에서 외관만 촬영)
- **기술**: 웹 페이지 하나(Leaflet 지도) + 작은 파이썬 서버 + 멀티모달 LLM API(JSON 출력)
  - 색 계산은 미리 만든 GeoJSON과 서버의 규칙 함수로 한다.
  - 폰에서 저장하면 대시보드가 몇 초마다 새로 불러온다.

## 7. 보여 줄 숫자

| 숫자 | 출처 |
|---|---|
| 첫 지도: 빨강 24곳 / 주황 65곳 / 초록 41곳 | 27번 규칙, 실제 데이터 |
| AI 체크리스트와 팀 판정의 일치율 | 시연 사진 20~30장 |
| 점검 일지 작성 시간: 수기 vs AI 초안 | 팀원 실측 |

## 8. 마일스톤

| # | 완료 기준 |
|---|---|
| M1 | 실제 158호로 27번 색 규칙 지도가 뜬다 |
| M2 | 사진을 넣으면 AI가 체크리스트·단계 후보·일지 초안을 JSON으로 낸다. 시연 사진 응답은 캐시해 둔다 |
| M3 | 폰 점검·제보 → 대시보드 색 변화까지 한 바퀴가 돈다 |
| M4 | 네트워크 없이도 시나리오를 끝까지 재생할 수 있고, 녹화본이 있다 |

## 9. 팀이 정할 것

1. **시연 지역 1~2곳:** 빨강이 있고 피해 범위가 큰 곳(선부동, 부곡동 등) 권장
2. **시연 사진:** 언제 어디서 찍고, 정답 판정은 누가 할지
3. **화면 만들기:** 웹 페이지(권장)와 Streamlit 중 무엇으로 할지
4. **"3개월 뒤" 버튼:** 넣을지(시간 흐름을 보여 주는 장면)
