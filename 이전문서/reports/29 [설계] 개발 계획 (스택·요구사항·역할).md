# 개발 계획: 기술스택·요구사항·역할 (6시간)

> 조건: 개발 6시간, 개발자 2명(JS 1, Spring Boot 1) + 비개발 2명, Codex·Claude 사용. 발표는 PPT, 시연은 **노트북에서 잠깐 부분 시연**(폰 화면 없음). AI는 Gemini API(무료), 예비로 GPT-4o.
> 기준 문서: `27`(색 규칙), `28`(MVP). **원칙: 시연 장면 3개만 확실히 돌아가면 된다.**

---

## 1. 시연에서 꼭 돌아가야 할 장면 3개

| # | 장면 | 필요 기능 |
|---|---|---|
| A | 안산 지도에 빈집 130곳이 긴급도 색으로 뜸. "빨강 24곳" | 지도 + 색 + 요약 카드 |
| B | 빈집을 눌러 사진을 올림 → AI가 4부문 체크·단계 후보·일지 초안을 보여 줌 → 1단계 확정 → 진한 빨강 | 점검 등록 + AI 판독 |
| C | 조치 완료 → 초록, 다음 점검 6개월 뒤 | 상태 전이 |

나머지(제보 목록, 3개월 뒤 버튼)는 시간이 남으면 넣는다.

---

## 2. 기술스택

| 부분 | 선택 | 이유 |
|---|---|---|
| 화면 | **HTML + JS + Leaflet**(CDN), 빌드 도구 없음 | JS 개발자 1명이 바로 시작. 설정 시간 0 |
| 지도 타일 | OpenStreetMap | 키가 필요 없음 |
| 서버 | **Spring Boot**, REST 5개, 메모리 저장(Map) | Spring 개발자 담당. DB 없음 |
| AI | **Gemini API**(이미지 입력, JSON 출력), 서버에서 호출 | 무료. 키를 서버에 둠. 실패하면 GPT-4o로 교체 |
| 데이터 | 미리 계산한 `houses.json`(158호, 위경도, 피해 범위, 주기, 시작 색) | 이 세션에서 파이썬으로 생성 |
| 실행 | 노트북 localhost | 배포하지 않음 |

**플랜 B (3시간째에 서버 연결이 안 되면):** 프론트 단독으로 간다. 브라우저가 Gemini를 직접 부르고, 상태는 메모리에 둔다. Spring 개발자는 AI 프롬프트와 캐시 담당으로 바꾼다.

## 3. 요구사항

### 기능 (필수 = M, 선택 = S)

| ID | 요구사항 | 우선 |
|---|---|---|
| F1 | 지도에 방문지 130곳을 27번 규칙 색(진한 빨강·빨강·주황·노랑·초록)으로 표시 | M |
| F2 | 상단 요약 카드: 색별 개수 | M |
| F3 | 오른쪽 "먼저 갈 곳" 목록: 색 → 피해 범위 개수 → 기한 초과 일수 순 | M |
| F4 | 점 클릭 → 상세 패널: 색 이유, 위해 단계, 다음 점검일, 피해 범위 조건, 타임라인 | M |
| F5 | 상세 패널에서 사진 업로드 → AI 판독 결과(4부문 체크, 단계 후보, 일지 초안) 표시 | M |
| F6 | 담당자가 단계 확정(1·2·3단계 / 이상 없음) → 색·다음 점검일 갱신 | M |
| F7 | "조치 완료" 버튼 → 초록, 다음 점검 = 오늘 + 6개월 | M |
| F8 | "30일 제보" 탭: 미리 넣은 제보 목록, D-day 오름차순 | S |
| F9 | "3개월 뒤" 버튼: 기준일을 옮겨 색 변화를 보여 줌 | S |
| F10 | 제보 등록 폼: 기존 빈집 연결 또는 미등록 확인 요청 | S |

### 비기능

| ID | 요구사항 |
|---|---|
| N1 | **시연 안정성:** 시연 사진 3장의 AI 응답을 캐시하고, API가 실패하면 캐시로 응답 |
| N2 | AI 응답 10초 이내. 기다리는 동안 로딩 표시 |
| N3 | 로그인과 보안은 없음. 노트북 한 대에서 동작 |
| N4 | 화면은 한국어. 프로젝터에서 잘 보이게 글자를 크게 |
| N5 | 개별 주소는 띄우지 않음(지번 가림 그대로). 담당자 화면이라는 설정 |

## 4. 데이터·API 약속 (처음 30분 안에 합의)

**houses.json 한 항목**
```json
{ "id": "선부동-1089-1**", "lat": 37.33, "lng": 126.81, "dong": "선부동", "units": 4,
  "type": "다세대", "grade": 1, "plan": "안전조치",
  "exposure": { "facility": true, "cluster": true, "density": true },
  "cycleMonths": 6, "lastChecked": "2026-01-01", "hazardStage": "시판정",
  "actionDone": false, "timeline": [] }
```

**REST API (Spring)**

| 메서드 | 경로 | 하는 일 |
|---|---|---|
| GET | `/api/houses?today=2026-11-08` | 전체 목록 + 계산된 `color`, `reason`, `nextDue` |
| POST | `/api/houses/{id}/inspect` (사진) | Gemini 판독 → `{checks, stageCandidate, journal}` |
| POST | `/api/houses/{id}/confirm` `{stage}` | 단계 확정 → 갱신된 항목 |
| POST | `/api/houses/{id}/action-done` | 조치 완료 → 갱신된 항목 |
| GET | `/api/reports` | 미리 넣은 제보 목록(S) |

**AI 출력 JSON**
```json
{ "checks": { "무단출입범죄": true, "화재설비": false, "위생환경": true, "붕괴위험": false },
  "signals": ["출입 흔적", "창호 파손", "쓰레기 적치"],
  "stageCandidate": 1, "confidence": 0.8,
  "journal": "현관문이 열려 있고 창호 1곳이 파손됨. 내부에 쓰레기 적치. 무단출입 우려로 1단계 후보." }
```

**색 계산은 서버 한 곳에서만 한다**(27번 규칙). 프론트는 받은 `color`를 칠하기만 한다.

## 5. 역할

| 사람 | 맡는 것 |
|---|---|
| **JS 개발자** | 지도, 요약 카드, 목록, 상세 패널, 사진 업로드 화면(F1~F7 화면 쪽) |
| **Spring 개발자** | REST 5개, 27번 색 계산 함수, Gemini 호출, 응답 캐시(N1) |
| **비개발 A** | 시연 사진 3~5장 준비(인터넷의 공개 이미지 또는 팀 촬영). AI Studio에서 프롬프트를 시험해 결과 JSON을 저장(캐시 재료) |
| **비개발 B** | PPT, 시연 대본(장면 A·B·C), 발표 숫자 정리(24·26·27번 문서) |
| **Claude(이 세션)** | `houses.json` 생성, AI 프롬프트 초안, 색 계산 규칙 의사코드 |
