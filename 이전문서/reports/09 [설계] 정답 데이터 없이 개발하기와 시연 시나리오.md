# 정답 데이터 없이 개발하기와 시연 시나리오

## 핵심 답

**실제 빈집 목록이 없어도 지수는 만들 수 있다.** 부산 SOS 지수도 계산할 때는 정답을 쓰지 않는다. 8개 지표를 등급으로 나눠 평균 낸 것이 전부다 [확인, 부산연구원 PDF]. 정답(동별 빈집 수 5,093채)은 **어떤 지표를 쓸지 고를 때만** 썼고, 그 선택은 이미 부산이 해 놓았다. 안산판은 그 결과를 물려받아 시작하고, 정답은 다른 경로로 조금씩 모은다.

정답이 없을 때 쓰는 방법은 여섯 단계 사다리로 생각하면 된다. 아래로 갈수록 정답이 많아지고 정확해진다. **해커톤에서는 1~4단계, 실서비스에서는 5~6단계**를 쓴다.

## 1. 정답 없이 시작하는 여섯 단계

| 단계 | 방법 | 필요한 정답 | 해커톤에서 | 
|---|---|---|---|
| 1 | **지식 물려받기:** 부산이 정답으로 골라 준 지표와 방향(공시지가는 낮을수록, 고령화는 높을수록 위험)을 그대로 쓰는 규칙 점수 | 0개 | 기준선으로 반드시 만든다 |
| 2 | **다른 지역 정답으로 학습:** 빈집을 한 채 단위로 공개한 지자체 데이터로 "이 건물이 빈집일 확률" 모델을 학습하고, 안산 건축물대장에 적용 | 다른 지역 공개 데이터 | 가능. 아래 주의 참고 |
| 3 | **확실한 정답 일부 쓰기:** 공개 자료로 빈 게 확실한 곳(이주 완료된 정비구역 단지 등)을 "확실한 빈집"으로 두고 학습 | 수십~수백 채 | 가능 |
| 4 | **팀이 직접 정답 만들기:** 시범 격자 1~2곳에서 외관 조사로 100~200동을 판정 | 팀 수집 | **해커톤 전 반드시** |
| 5 | **집계 정답으로 검증:** 정보공개청구로 304호의 동별 집계를 받아, 모델이 예측한 동별 합계와 비교 | 동별 숫자 | 청구가 제때 오면 |
| 6 | **시스템이 정답을 만든다:** 순찰대 점검 결과("빈집 맞음/아님")가 쌓이면 재학습 | 운영 중 계속 | 시뮬레이션으로만 보여 줌 |

### 2단계: 다른 지역 빈집 데이터로 학습하기

- 공공데이터포털에 빈집을 한 채 단위로 공개한 지자체가 있다 [검색요약].
  - **공주시 빈집 정보:** 시도·시군구·읍면동, 도로명, 주택유형, 건축면적, 건축연도, 빈집등급
  - **양산시 빈집 현황:** 소재지, 건축물 구조, 연면적, 빈집등급
  - 용인·창원·고창·김천은 등급별 건수 같은 집계 위주로 보인다.
  - 정확한 컬럼과 데이터 ID는 data.go.kr에서 "빈집"으로 검색해 상세 페이지에서 직접 확인해야 한다.
- **방법:** 그 지역 건축물대장 전체를 받아 "빈집 목록에 있는 건물 = 1, 나머지 = 0"으로 붙인다. 건축연도, 구조, 면적, 용도, 층수 같은 건물 특징으로 분류 모델(그래디언트 부스팅 등)을 학습한다. 같은 특징을 안산 건축물대장에서 뽑아 확률을 매긴다.
- **주의:** 공주·양산은 안산과 도시 성격이 다르다. 그대로 믿으면 안 된다. 쓰는 방법은 두 가지다.
  - 모델 결과를 1단계 규칙 점수와 비교해 "두 방법이 같이 높게 본 곳"을 우선한다.
  - 4단계 안산 현장 표본으로 맞는지 확인한다. 맞지 않으면 그 자체를 발표에서 솔직히 보여 준다.

### 3단계: 확실한 빈집으로 학습하기

- 정비구역에서 **이주가 끝난 단지**는 공개 자료로 빈 것이 확실하다. 주공5단지 2구역 이주 완료 보도가 있다 [검색요약, 날짜 미확인].
- 이런 "확실한 빈집"만 있고 "확실히 사람이 사는 집" 목록은 없을 때 쓰는 방법이 **PU 학습**(Positive-Unlabeled)이다. 확실한 빈집과 나머지 전체를 비교해 빈집다운 특징을 찾는다.
- 주의: 이주 완료 단지는 아파트라 구도심 다가구 빈집과 특징이 다르다. 정비 공가 전용 모델로만 쓰고 구도심과 섞지 않는다.

### 4단계: 팀이 직접 정답 만들기 (가장 중요)

- **어디서:** 시범 격자 1~2곳. 정비구역 한 곳 주변, 구도심 저층 골목 한 곳.
- **무엇을:** 공공도로에서 보이는 외관만 본다. 체크리스트는 우편물·전단 적체, 계량기 상태, 문·창 개방이나 파손, 투기물, 잡초·방치, 야간 불빛 유무다.
- **어떻게:** 팀원 두 명이 같은 건물을 따로 판정해 일치율을 잰다. 일치하지 않는 건 "애매"로 둔다. 100~200동이면 검증용으로 충분하다.
- **이 데이터의 쓸모가 세 가지다.**
  - 1·2·3단계 모델 중 무엇이 안산에서 맞는지 고르는 검증셋
  - AI 사진 판독이 사람 판정과 얼마나 일치하는지 보여 주는 증거
  - 시연에 쓰는 실제 현장 사진과 영상

## 2. 보고 싶지만 못 보는 데이터와 우회 방법

| 데이터 | 왜 필요한가 | 왜 못 보나 | 해커톤 우회 | 실서비스 때 |
|---|---|---|---|---|
| **안산 빈집 304호 목록** | A축 정답 | 시 비공개 | 2·3·4단계, 동별 집계 정보공개청구 | 시 내부 데이터와 연동 |
| **전기·수도 사용량** | 빈집 판정 핵심 신호 | 한전·상수도 비공개 | 외관 신호(우편물 적체, 계량기, 야간 불빛)를 AI 사진 판독으로 대신 | 시는 법적 근거로 요청할 수 있다(소규모주택정비법 시행령 8조의3) [확인] |
| **전국 AI 빈집 위험 예측 지도** | A축을 대신할 수 있음 | 지자체 전용 [확인] | 자체 A축으로 만들고 "교체 가능한 입력"으로 설계 | 시가 받으면 끼워 넣음 |
| **112 신고·범죄 발생 지점** | B축 검증 | 경찰 내부 | 아래 참고: B축을 범죄 결과가 아니라 공백(원인)으로 정의 | 경찰과 협약 |
| **관제 CCTV 영상·알람** | 실제 감시 여부 | 비공개 | CCTV 위치 표준데이터로 거리만 계산 | 관제센터 연동 |
| **보안등 관리대장·고장 이력** | B축 조명 | 안산 표준데이터 포함 여부 미확인 | 야간 걷기 영상으로 실측, 정보공개청구 | 도로조명팀 대장 연동 |
| **비상벨 작동 이력** | B축 | 비공개 | 외관 상태만 확인 | 관리 부서 연동 |
| **정비구역 이주 일정** | A축 정비 단계 | 일부만 고시 | 공개 고시문을 AI로 추출, 나머지 정보공개청구 | 도시정비과 연동 |
| **실거주 인구** | 인구 지표 보정 | 생활인구 안산 공개 여부 미확인 | 주민등록 인구를 쓰고 한계를 명시 | 통신 생활인구 구매·협약 |
| **순찰대 활동 기록** | 6단계 재학습 | 존재하지 않음 | 팀이 순찰대 역할을 해서 직접 생성 | 서비스가 쌓음 |

### 범죄 데이터가 없는 것은 오히려 장점이다

B축을 "범죄가 일어난 곳"이 아니라 **"밤에 아무도 안 보는 곳"**(CCTV에서 멀고, 등이 꺼져 있고, 비상벨이 없는 곳)으로 정의한다. 이렇게 하면 세 가지가 좋아진다.

- 경찰 데이터 없이도 공개 데이터로 계산된다.
- 범죄 예측 치안이 받는 비판(신고가 많은 동네가 계속 위험으로 찍히는 편향)을 피한다.
- 결과가 곧 조치다. "이 칸은 등 2개 수리, CCTV 사각"처럼 시가 바로 고칠 수 있는 것만 나온다.

범죄 데이터는 화면 배경(생활안전지도 범죄주의구간 WMS)과 경찰서 단위 통계로 "왜 안산인가"를 설명할 때만 쓴다.

### 현장 수집할 때 지킬 것

- **비상벨은 절대 누르지 않는다.** 실제 출동으로 이어질 수 있다. 외관만 본다.
- 사유지에 들어가지 않는다. 공공도로에서 보이는 것만 찍는다.
- 사진 속 얼굴, 번호판, 문패는 AI로 자동 가린다.
- 시연 화면에도 실제 빈집 주소를 띄우지 않는다. 격자 단위로 보이거나, 핀 위치를 일부러 조금 흐트러뜨린다.

## 3. 시연 시나리오: 지자체 + 순찰대

### 준비물

- **노트북(프로젝터):** 지자체 대시보드. 안산 격자 SOS 지도, 조치 목록, 리포트.
- **스마트폰(화면 미러링):** 순찰대 앱. 점검 경로, 사진 점검, 걷기 영상 업로드.
- **인쇄한 현장 사진 몇 장:** 심사위원이 직접 찍어 보게 할 용도.
- **백업:** 전체 시연 녹화 영상, AI 응답 캐시, 인터넷 없이 도는 모드.

### 모든 화면에 데이터 출처 표시

레이어마다 작은 배지를 단다. **[실데이터]** 공공데이터, **[팀 수집]** 현장 사진·영상·판정, **[가상]** 비공개 데이터를 흉내 낸 값. 심사위원이 "이거 진짜 데이터냐"고 묻기 전에 답이 보이게 한다.

### 5분 시나리오

| 시간 | 화면 | 보여 줄 것 | 데이터 |
|---|---|---|---|
| 0:00~0:40 | 슬라이드 | 범죄 5년 연속 5등급, 노후계획도시와 정비구역 28곳, 정부의 "매달 4일 빈집 점검" 과제에 도구가 없다는 문제 | 실데이터 |
| 0:40~1:30 | 대시보드 | 안산 격자 지도. 부산식(단순 평균)과 안산식(치안 축 추가)을 좌우로 비교. 순위가 바뀐 칸을 짚는다 | 실데이터 |
| 1:30~2:00 | 대시보드 | SOS 칸 하나 클릭 → AI가 "왜 SOS인지" 설명(노후 저층 비율 높음, CCTV 180m, 보안등 간격 넓음) | 실데이터 + AI |
| 2:00~2:20 | 대시보드 → 폰 | "이번 달 4일 점검" 버튼 → 순찰대 폰에 1시간 경로와 지점 6곳 도착 | 실데이터 |
| 2:20~3:10 | 폰 | **라이브:** 심사위원에게 인쇄한 현장 사진을 폰으로 찍게 한다. AI가 체크리스트를 자동으로 채운다(문 개방, 우편물 적체). 얼굴·번호판 자동 가림 | 팀 수집 + AI |
| 3:10~3:40 | 폰 | 미리 찍은 5분 야간 걷기 영상을 30초로 빨리 감아 재생. 꺼진 등 3개와 어두운 구간이 지도에 찍힌다 | 팀 수집 + AI |
| 3:40~4:20 | 대시보드 | 방금 결과로 해당 칸 점수가 갱신된다. 조치 목록이 부서별로 자동 배분된다(도로조명팀 등 수리, 건축과 개구부 폐쇄, 지구대 순찰 요청). "빈집 밀집구역 근거 리포트"가 한 장으로 생성된다 | AI |
| 4:20~4:50 | 대시보드 | **검증 화면:** AI 사진 판독 vs 팀 판정 일치율, 규칙 점수 vs 타 지역 학습 모델 vs 현장 결과 비교 | 팀 수집 |
| 4:50~5:00 | 슬라이드 | 확장: 경찰·관제센터·주민 화면 한 장씩, 순찰이 쌓일수록 지수가 똑똑해진다는 구조 | — |

### 라이브로 할 것과 미리 할 것

- **라이브:** 사진 판독(몇 초면 끝남), 대시보드 갱신, 리포트 생성.
- **미리:** 야간 영상 처리(시간이 오래 걸림), 지수 계산, 경로 생성의 무거운 부분. 결과를 저장해 두고 재생한다.
- 라이브 단계마다 실패하면 바로 캐시 결과로 넘어가는 버튼을 숨겨 둔다.

### 가장 강한 장면 하나

**심사위원이 찍은 사진 한 장이 3초 뒤 시 대시보드의 점수와 조치 목록을 바꾸는 장면**이다. "순찰이 곧 점검이 되고, 점검이 곧 데이터가 된다"는 메시지가 이 한 장면에 다 들어 있다. 시간이 모자라면 다른 걸 줄이고 이것만은 남긴다.

## 4. 최소 기술 구성 (참고)

| 부분 | 선택지 |
|---|---|
| 지도 | Leaflet 또는 deck.gl, 격자는 GeoJSON |
| 백엔드 | FastAPI 같은 가벼운 API, SQLite 또는 PostGIS |
| 사진 판독 | 멀티모달 LLM API에 체크리스트 JSON 형식으로 답하게 지시 |
| 얼굴·번호판 가림 | 공개 얼굴 검출 모델 + 블러 |
| 영상 등 검출 | 프레임 추출 후 밝은 점 검출 또는 객체 검출 모델, 상대 밝기 계산 |
| 지수 계산 | pandas로 등급화(Jenks), scikit-learn으로 군집·분류 |
| 설명·리포트 | 지표 기여도 계산 후 LLM이 대상별 문장 생성 |
| 실시간 갱신 | 대시보드가 몇 초마다 새로 불러오기(폴링)로 충분 |
